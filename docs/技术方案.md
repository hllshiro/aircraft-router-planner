## 一、背景与目标

### 1.1 背景

旧项目 `simple-router-planner`（CLI 二进制 `rplan-cli`，v0.4.0）为纯 Rust 实现的确定性 3D 航路规划 CLI 引擎，采用"宏观拓扑路由 → 安全飞行走廊 → 加权 A\*"三层架构。经实测存在两大硬伤与多项功能缺口，决定放弃旧实现、基于原始功能需求重构，新项目命名为 **AircraftRouterPlanner**。

### 1.2 旧项目问题（重构动机）

| 类别 | 问题 | 说明 |
|------|------|------|
| 性能 | 100km+ 多雷达场景超时 | 宏路由中间点导致某段走廊内无解 → 回退**无约束搜索**（O(N³) 灾难），与 README 声称的毫秒级不符 |
| 物理正确性 | 路径钻入地下（-4500m） | 无地形/地面约束，A\* 把"从雷达球体下方穿过"视为合法路径 |
| 功能缺口 | 限飞区无法表达 | 只有禁飞区棱柱一种表达，无法表达"仅特定高度层禁入" |
| 功能缺口 | 固定翼/旋翼机不区分 | 仅一个 VehicleProfile，无 aircraft type 分流 |
| 功能缺口 | 输出不平滑 | 只有折线抽稀，波浪形锯齿未拟合成曲线 |
| 功能缺口 | 无地形数据输入 | 需求中"内置低精度数据/经纬度匹配"均未实现 |
| 功能缺口 | 蓝方兵力/武器未实现 | 影响 TargetZone radius 与武器投放区约束 |

### 1.3 目标

- 满足全部原始功能需求（见第二节）
- 性能硬指标：**每百公里 ≤ 3s，绝对不能崩溃**
- 确定性：固定种子 100% 可复现（跨平台一致）
- 交付形态：CLI 二进制 + stdin/stdout JSON 管道，可交叉编译 Linux musl / Windows MSVC 静态分发；**单二进制 + 内置地形数据文件**（数据不打进二进制，作为发布附带文件随包分发，默认 `data/` 目录，可替换/切换，见 4.2.5）；**发布版仅含此两者（主管裁决）——Demo 层为开发期工具，不随发布版分发**（见 3.x/Phase 5/八章）

## 二、原始功能需求回顾

### 2.1 航路规划功能

- 从 A 点出发，到达 B 点一定范围（范围大小视武器而定）
- 考虑红方雷达探测范围：简化为球体（大于实际范围）；可能要引入探测概率（随距离衰减）或压制后距离，否则可能无可用路径
- 考虑飞机性能：最小转弯半径、最大爬升角、最大转弯角；**兼容固定翼和旋翼机**；**飞机速度**（十轮主管裁决：原始需求遗漏项）——速度影响转弯半径（ρ = v²/(g·tan φ_max)）、爬升率、雷达探测区暴露时间（探测概率与穿越时长相关）、发射包线速度窗；**速度-转弯半径物理耦合（十二轮共识）**：ρ ∝ v²，高速+小半径组合须过 A6 自洽校验（见 4.2/5.2）
- 考虑禁飞区：从地面到无限高禁止进入
- 考虑限飞区：指定高度禁止进入
- 输出美化：平滑点集（波浪形拟合为曲线）；抽稀点集（同一航路段不应有太多中间点）
- 考虑地形遮蔽：飞机不能撞山；地形可为飞机提供可用通道

### 2.2 性能需求

- 计算效率：每百公里 ≤ 3s
- 绝对不能崩溃（确定性、容错）

### 2.3 输入/输出

- 输入：蓝方兵力、武器；红方力量部署；地形数据（考虑内置低精度数据；算法如何匹配地形数据经度）
- 输出：蓝方航路点集

## 三、技术选型

### 3.1 语言：Rust（2021 edition，沿用）

旧项目问题全部出在算法与实现，不在语言选型。Rust 满足三条硬性需求：

| 需求 | Rust 支撑 |
|------|-----------|
| 性能（≤3s/100km，不崩溃） | 无 GC、内存安全、零成本抽象 |
| 确定性（固定种子可复现） | 无未定义行为，跨平台一致 |
| 交付（CLI + 交叉编译分发） | cargo 生态，Linux musl / Windows MSVC 静态二进制（旧 CI 已打通） |

### 3.2 三方库清单

**选型原则：克制引入。** 库只做"基元与索引"，核心算法（A\*/走廊/宏路由/地形约束）仍自研。

#### A. 保留沿用（旧项目已验证）

| 库 | 用途 |
|----|------|
| `serde` + `serde_json` | 输入/输出 JSON 契约 |
| `rand` ^0.10 | 确定性随机种子（FNV-1a 噪声场沿用，多机协同平行航线） |

#### B. 新增核心依赖（第一版，8 个）

| 库 | 用途 | 对应痛点/需求 |
|----|------|---------------|
| `nalgebra` | 3D 向量/矩阵基元、局部 ENU 坐标变换 | 替代手写 Point3D，避免手写几何隐性 bug |
| `rstar`（**锁 ^0.12**） | R-Tree 空间索引：雷达/禁飞区/地形块空间查询 | 多障碍物下碰撞检测与邻域查询退化（O(N³) 隐患）；版本被 geo 0.33 锁死，**不可用最新 0.13**（见 3.2.1 版本锁定） |
| `geo`（含 `geo-types`） | 测地线距离/方位计算（geographiclib-rs）、几何运算；**UTM 转换用纯 Rust `utm` crate 或自研**（geo 不提供，见 3.2.1 红线②） | 输入为经纬度+高程，100km 级航路与雷达覆盖依赖投影正确性 |
| `thiserror` | 派生错误类型，JSON 错误码输出仍可控 | 替代手写 error.rs |
| `clap`（derive 模式） | CLI 参数（`--seed/--input/--output/--config`），stdin 管道仍为默认模式 | 旧版无参数、测试与运维不便 |

#### C. 针对性补强（第二版引入）

| 方案 | 用途 | 决策依据 |
|------|------|----------|
| `dubins_path(s)`（先评估） | 固定翼最小转弯半径平滑（2D 水平路径） | 3D Dubins 自研是重活（垂直/水平剖面耦合）；**先引 2D crate 评估**，不达标则自研 2D Dubins |
| 手写样条平滑 | 波浪形锯齿拟合为曲线（Catmull-Rom/Chaikin） | 代码量小（几十行），无需库 |
| 手写 ray-casting | 禁飞区/限飞区多边形底面包含判断 | 区域数量少时足够；后续需要多边形布尔/缓冲再引入 geo 能力 |
| 自研地形读取（trait 化） | SRTM/HGT `.hgt`（裸 16-bit 大端网格）与自建紧凑格式（16-bit + 分块差分 + Zstd） | 格式解析简单；格网映射是线性变换。**SRTM 两个分发形态均覆盖**：USGS SRTMGL1/3 = `.hgt`（本实现）；CGIAR SRTM v4 = GeoTIFF（走 `geotiff` 实现）。**已核实（2026-08）：无更优运行时替代**——`.hgt` 是裸格式，读取+双线性插值仅几十行；内置紧凑格式块解压走 `ruzstd`（纯 Rust）；`htg`（268 下载/1 star/HTTP 微服务定位）与项目场景错位，`srtm_reader` 列为备选评估（见 3.2 D） |
| `geotiff`（georust，纯 Rust） | **运行时 GeoTIFF 地形读取**（发布版本必含，`TerrainSource` 的 `GeoTiffSource` 实现） | 需求：发布版本支持 GeoTIFF 格式地形。依赖树实测全纯 Rust（geo-types ^0.7 / num-traits / num_enum / tiff ^0.9，proj 仅 dev），**不破坏静态单二进制**；⚠️ v0.1.0 后作者预告 breaking changes，锁版本 + 单测兜底（见 3.2.1 版本锁定） |
| `dted2`（纯 Rust） | **运行时 DTED/DTED2 地形读取**（发布版本必含，`TerrainSource` 的 `DtedSource` 实现） | 需求：发布版本支持 DTED/DTED2。`DTEDData::read()` + `get_elevation(lat,lon)` 直接匹配 `TerrainSource` 接口；支持 Level 0/1/2（DTED2 = Level 2，30m）；依赖全纯 Rust（nom 7 / num-traits / thisenum / thiserror 1）；⚠️ 2024-08 后未更新但 1.0 稳定，锁版本 + 单测兜底 |
| `ruzstd`（纯 Rust） | **内置地形数据（自建紧凑格式）Zstd 分块解码**（压缩在开发期由 zstd CLI 完成，运行时只解码） | 8GB 全球数据 → 内置压缩包 ≤800MB（见 4.2.5）；**纯 Rust 解码器、零 C 依赖**，不破坏 musl 静态单二进制（见 3.2.1 红线④）；支持按块解压（LRU 缓存），内存可控 |

#### D. 可选 / 后置

| `srtm_reader` 0.5.3 | `.hgt` 读取备选评估（运行时零依赖、2026-07 活跃维护） | 若 Phase 0 自研 reader 暴露问题，用其替代自研解析，`TerrainSource` trait 接口不变 |

### 3.2.1 静态编译约束（红线，2026-08 核实）

**交付形态：单二进制可执行文件（Linux musl / Windows MSVC 静态）。** 所有选定库均为纯 Rust、零 C 依赖；以下四条红线保证该形态不被破坏：

1. **nalgebra 仅默认特性，禁用 `blas`**：启用会拉 `openblas-src`（C/Fortran），破坏静态编译。
2. **geo 不启用 `proj` feature**：它是 PROJ C 库绑定；geo 本身只提供测地线算法，**不做投影**。投影层自研：主算面为自定义 TM（横轴墨卡托公式，约 50 行，见 4.2.3），输出插件 UTM/GK 3° 为同族参数化公式——**不要**用 `proj` crate。
3. **flate2 保持默认 rust_backend**：不启用 `zlib`/`zlib-ng-compat`（C 后端）。tiff 传递依赖自动满足；项目直接引入时注意。
4. **`ruzstd`（Zstd 解码）为纯 Rust 实现**：内置地形数据运行时解码走 `ruzstd`，不引入 libzstd（C）；压缩仅在开发期由 zstd CLI 完成，运行时零外部工具。

**版本锁定（2026-08 crates.io 实测）**：主程序直接依赖版本必须与关键库 normal 依赖对齐，否则 Cargo 双大版本共存（体积 + API 分裂）。

| crate | 主程序锁定 | 依据（normal 依赖实测） | 说明 |
|-------|-----------|--------------------------|------|
| `rand` | **^0.10（0.8 不可用）** | geo 0.33.1 → `rand ^0.10.0`（**非可选**） | geo 必带 rand 0.10；主程序用 0.8 即双版本。FNV-1a 噪声场不依赖 rand 大版本 API，0.8→0.10 迁移成本小 |
| `rstar` | **锁 ^0.12（0.13 不可用）** | geo 0.33.1 → `rstar ^0.12.0`（**非可选**） | rstar 最新 0.13，但 geo 锁 0.12；主程序升 0.13 即双版本 |
| `geo-types` | ^0.7 | geo 0.33 → `^0.7.19`；geotiff → `^0.7` | 已统一 |
| `serde` | ^1 | 全部 ^1 | 已统一 |
| `thiserror` | ^2 | geo-types 0.7.20 → `^2.0.19` ✓；**dted2 1.0.0 → `^1`（非可选）** | dted2 进运行时后 thiserror 1 进入交付二进制；双版本体积影响可忽略，可接受 |
| `dted2` | **^1（进运行时，锁 1.0.0）** | 依赖全纯 Rust（nom 7 / num-traits / thisenum / thiserror 1）；`get_elevation(lat,lon)` 直接匹配 `TerrainSource` | 发布版必含（DTED/DTED2）；2024-08 后未更新但 1.0 稳定，锁版本 + 单测兜底，升级需单独评审 |
| `tiff` | 不直接依赖 | geotiff 0.1.0 → `tiff ^0.9`（最新 0.11.3） | geotiff 内部封装，无影响 |
| `geotiff` | **^0.1（进运行时，锁具体版本）** | 依赖全纯 Rust；geo-types ^0.7 与 geo 统一 ✓ | 发布版必含；v0.1.0 后有 breaking 预告，锁定具体版本 + 地形单测兜底，升级需单独评审 |

> 排查方法（纳入 5.2 静态编译回归同批 CI）：`cargo tree -d` 检查重复依赖，`cargo tree -e normal` 检查 C 依赖。

**GDAL 定位（定案）**：仅作为**开发期离线预处理工具**（任意格式 DEM → 重采样/裁剪/填洞/重投影），**不进运行时**。运行时地形读取全部由纯 Rust crate 承担：GeoTIFF → `geotiff`、DTED/DTED2 → `dted2`、SRTM/HGT → 自研（均发布版必含，见 3.2 C）。

### 3.3 依赖规模对比

| 项目 | 核心依赖数 | 说明 |
|------|-----------|------|
| simple-router-planner | 3 | serde/serde_json/rand，全部几何算法手写 |
| AircraftRouterPlanner 第一版 | 8 | + nalgebra/rstar/geo/thiserror/clap，全部是"基础件"而非"算法库" |
| AircraftRouterPlanner 第二版 | 8 + dubins_path(s) + geotiff + dted2 + ruzstd | 仅按需增加；geotiff/dted2 为发布版必含；ruzstd 为内置数据 Zstd 解码（纯 Rust） |

### 4.1 模块划分（Cargo workspace）

```
│       ├── router.rs     # 回退层：宏观拓扑路由（FMM 数值不稳/强不连续时启用）

```

### 4.2 核心算法架构（分层解耦）

**决策依据（对"A\* 在三维场景下不适合"的澄清）**：A\* 是图搜索算法，与维度无关。真正不适合的是"均匀网格离散化 + 运动学事后剪枝"——26 向邻居只能产生锯齿折线、转弯半径/爬升角在网格上无法表达、加密网格状态爆炸（O(N³)）、启发式在强非平滑代价场（雷达/地形）中退化。正确药方是分层解耦：粗层图搜索定走廊，细层运动基元保可行。

```
粗层：FMM 快速行进法（粗网格 1-2km）传播 地形+雷达+禁飞区合成代价场
    → 输出：全可达域 + 可行走廊（一次计算，多机共享）
细层：走廊内运动基元搜索（固定翼 2D Dubins 基元 / 旋翼机陡爬升基元，
      运动学约束前置预生成，而非事后剪枝）
    → 输出：运动学可行航段
后处理：Theta* 去锯齿 + Dubins/样条拟合 + 贪心抽稀
    → 输出：最终平滑路径
回退层：宏观拓扑路由（FMM 数值不稳/强不连续时启用，接口预留）
```

**网格维度定稿（十三轮共识，数据结构项）**：代价场/Grid/LOS mask 统一为 **2D 水平网格 + 50m 固定层高垂直分层**（不自适应，层数 = ceil(任务高度范围/50m) + 安全余量）；**限飞区高度吸附最近层**（限飞 [alt_min, alt_max] 映射到覆盖该区间的最小层集合）；粗层水平 1-2km、细层水平 152.87m（数据分辨率，见 4.2.5）；**z 分辨率 50m 写入数据契约**（`z_resolution_m: 50`），直接决定 Grid/代价场/LOS mask 数据结构与内存量级；粗层软代价仅作收敛手段、硬断言兜底（见 4.2.1/4.2.2；层厚下界条款与 50m 固定层高兼容：min 限飞区厚度 < 100m 的薄层由 4.2.2 下界条款与细层连续高度校验兜底，不得被固定层高吞掉）。

**关键改进（针对旧项目硬伤）：**

| 改进点 | 方案 |
|--------|------|
| **粗层 FMM 代价场** | 单次传播给出全场可达域，直接命中"到达 B 点一定范围"需求；多机多起点时代价场全场复用（架构级红利）；确定性、O(NlogN)、无启发式误差 |
| **运动学约束前置** | 固定翼/旋翼机各自预生成运动基元库，运动学可行性在基元生成时保证，而非节点扩展时即时过滤 |
| **杜绝无约束搜索回退** | 走廊内无解时不再回退到全局无约束搜索；**无解出口按序执行：① 放宽威胁约束（压制/探测概率，见 4.2.1）→ ② 放宽目标范围 → ③ 走廊细分/重路由 → ④ 明确报错**，保证 3s 预算内收敛 |
| **地形遮蔽约束** | 地形进代价函数（FMM 的天然形态）而非事后过滤；线段-地形射线求交作为路径合法性校验 |
| **限飞区表达** | 区域类型区分：`NoFlyZone`（地面→无限高）与 `RestrictedZone`（指定 [alt_min, alt_max] 高度层禁入）；**高度语义统一为绝对海拔（MSL）**，离地高度（AGL）输入须在解析层结合地形高程换算（见 4.2.2） |
| **机型分流** | `VehicleProfile` 增加 `aircraft_type`（FIXED_WING / ROTORCRAFT），**类别由外部参数显式提供（九轮主管裁决，不做自动识别）**，分别约束转弯半径、爬升角、转弯角；**机型性能参数来源规则（八轮共识）**：转弯半径/爬升角/转弯角/速度剖面等参数集**由输入显式提供**；输入缺省时**落入默认参数表占位值（Phase 0 校准）**，缺参不静默——`aircraft_type` 声明但参数集缺失时 fail-fast 显式报错；固定翼启用 Dubins 平滑，旋翼机可悬停/垂直机动；**旋翼机悬停机动显式建模（九轮共识）**：旋翼机悬停/极小转弯半径（r→0）在基元生成与样条拟合中须显式建模为合法机动分支（悬停/原地转向基元），**禁止除零退化**——不把 r→0 当数值异常；**`detection_probability`（飞机探测概率参数）用于隐蔽突防简化计算**（见 4.2.1）；**固定翼爬升角落点**：高程剖面独立插值时显式约束斜率 ≤ tan(最大爬升角)，且**水平基元所在高度层由剖面插值显式定义**（2D Dubins 水平段与三维走廊的调和，见 Phase 0 步骤 6 联合用例） |
| **转弯角显式落地** | 转弯角与半径约束仅在"圆弧表示 + 固定段长 L"下等价（纯折线表示下拐点曲率无穷）：**路径表示选型写死**（Dubins/混合 A* 圆弧，排除纯折线）；基元生成时校验 Dubins 圆弧圆心角 θ = L_arc/ρ ≤ θ_max（航段间航向差上限）；**ρ_min = max(输入半径, L/θ_max)** 合并进基元库预生成；Phase 3 二次校验新增逐段转角检查；转弯角满足率进 Phase 0 验收 |
| **速度为核心输入（十轮主管裁决）** | θ_max 与 ρ 在给定速度剖面下相互超定（v 已知则 ρ = v²/(g·tan φ_max)）——**速度由 `VehicleProfile` 显式提供（巡航速度或速度范围 [v_min, v_max]），缺省落入默认参数表占位值（Phase 0 校准），缺参 fail-fast**（与转弯半径/爬升角/转弯角同级）；**速度的物理作用**：转弯半径 ρ = v²/(g·tan φ_max)、爬升率 = v·sin γ、雷达探测区暴露时间（穿越时长 = 弦长/速度，探测概率与暴露时间相关）、发射包线速度窗；**速度-转弯半径物理耦合（十二轮共识）**：ρ 与 v 不是独立标定——固定翼 r_min ∝ v²/(g·tan φ_max)，**"高速 + 小半径"组合物理不可飞**：复验器强制 A6 物理自洽校验（`r_min ≥ v²/(g·tan φ_max)`），输入不自洽 → fail-fast 或按速度重算 r_min；细层基元按速度档绑定 r_min(v)；**速度 = 纯约束**（暴露时间/爬升率输入项），不做时间最优代价（时间维 out-of-scope）；转弯角/转弯半径约束的物理前提先在数据契约固定 |
| **TargetZone.radius 提前终止 + 武器→半径映射** | 目标球半径范围内即终止（修复旧项目已知限制）；**武器类型→半径由默认参数表换算**（查表/引信换算，见 4.2.1 默认参数表），武器输入真正参与规划 |
| **任务语义（蓝方兵力/武器为核心输入，六轮主管裁决）** | 蓝方兵力与武器是**任务航路规划的核心**（推翻 v0.8"未消费标注"）。**武器→发射阵位**：武器的射程/引信决定目标区半径（`TargetZone.radius`），航路目标是**进入发射阵位**（导弹射程覆盖目标 B）而非贴到 B 点；**发射阵位 = 指定的区域而非点（九轮主管裁决）**：`TargetZone` 支持**区域对象**（多边形/圆），由输入显式指定，或由"目标点 + 武器射程换算"生成圆形阵位区域；**到达判定 = 进入该区域**（区域包含判定，非"到点距离"）；末点**发射可用性**（航向/高度/速度落在武器发射包线内）显式列为到达判据之一——**区域进入与发射包线两者都满足才算到达，冲突时以发射包线优先**；武器 **Rmin–Rmax 环带语义（十轮共识）**：武器射程按 `[Rmin, Rmax]` 区间建模，**到达判定显式接入环带**——到达 = 进入发射阵位区域 ∧ 落点距阵位中心 ∈ [Rmin, Rmax]（大区域 + 小 Rmax 时"进入区域"≠"落在武器射程环带内"）∧ 发射包线（航向/高度/速度）；**环带当 FMM 目标集**：传播到环带即停（末端目标集，非单点），与代价场末端放松（≤判定半径×系数，见 5.2）配合改善终端到达性；**Rmin 未定值时显式告警**（不静默当无下限处理）；**带最小射程的武器不得停在 Rmin 内**；到达判定口径写死：**区域包含按水平面（2D 地面投影）判定 + 落点在环带内 + 高度落在发射包线高度窗内**（3D 分量以包线校验体现）；**终端 pose 下放平滑级（十轮共识）**：发射包线中的终端航向/高度/速度不只是到达判据，还须作为**平滑级输入**（Dubins 天然吃终端 pose，样条拟合以终端 pose 为边界条件）——否则合法走廊会因终端姿态不满足在判定级反复回退，撞 3s 预算；**航路核心目标 = 保证自身安全的前提下进入发射阵位 / 规避红方雷达探测**。两个任务场景（输入可显式声明，不声明时按 A1 通用语义）：① 挂载远程空地导弹的战斗机规划航路，在规避红方探测的前提下进入发射阵位执行任务（目标区半径=武器射程换算）；② 战斗机执行预定任务前规划规避航路，航路全程避开红方雷达探测（目标=规避，A2 探测代价为硬性约束） |
| **多机输入契约（十三轮共识，架构级）** | 需求 9/10"蓝方兵力武器→航路点集"为复数，v0.17 前全程按单 A→B 描述。输入侧 **`vehicles` 数组显式声明**（每机 = `VehicleProfile`（aircraft_type/速度/机动参数/探测概率）+ 起点 pose + 目标引用（同一或不同 B）+ 任务场景）；**一次 FMM 传播 + 多目标回溯**——同一目标组共享同一传播场（粗层只传播一次，各机在共享场上回溯各自走廊）；**不同目标按目标分组，代价场缓存按源键共享**（缓存键 = (起点源, 目标组)，同源同目标组不重传播）；**3s 预算按机线性分配**（N 机端到端总预算 = Σ 各机每百公里预算，共享传播部分摊薄不重复计，见 5.1）；**多机路径交叉检测（并入 P0-1）**：输出后处理检测多机航路空间交叉（纯几何检测，不涉时序——时间维 out-of-scope 不变），检出交叉时按任务优先级仲裁或高度分离（复用限飞区高度层语义）并显式告警，**不得静默输出空间交叉的航路集**；第一版不做编队协同搜索（多机/编队时序语义需求未定义，见 4.4 时间维 out-of-scope） |

#### 4.2.1 代价场融合规则

粗层 FMM 传播的代价场由四类输入合成，**融合规则在 Phase 0 数据契约中固定**——它直接决定"是否无解"，先于一切阶段排序：

| 输入 | 代价形态 | 融合方式 |
|------|---------|---------|
| 地形 | 低于地面 = 硬不可达（撞山）；接近地面/高坡度 = 软代价 | 硬阈值 + 加法项 |
| 雷达威胁 | **默认球形模型（保守探测范围上界）**（`detection_cost(point)` 经 trait 抽象，可载入外部模型）：球体内 = 高代价；**穿越合法但以探测概率为前提（十轮主管裁决）**——穿越路径必须用**探测概率模型**评估（`detection_probability_at(point, exposure_time)`，随距离衰减 + 暴露时间相关），`ThreatModel` trait 必须提供探测概率接口（探测概率从"回退分支"升级为**必选模型**，见 4.3）；穿越段累计探测概率作为路径代价/验收约束；**飞机探测概率参数**（`VehicleProfile.detection_probability`）折算隐蔽突防代价；压制后距离 = 随距离递减的软代价（压制仅输入显式声明时启用）；**LOS mask 乘子（十二轮共识，修正十一轮"收益项"）**：有地形文件时，遮蔽雷达视线的区域探测概率乘 mask 系数降权（`p_det = f(r)·mask_LOS`，硬 mask 非收益项——不需权重标定；代价场自然吸引路径利用地形掩护，非仅避撞，见 4.3）；**多雷达合成语义（十二轮共识）**：多雷达重叠区**默认球体口径保持覆盖 max（保守，与压制默认不生效原则一致）**；**探测概率模型启用时用概率并集 `1−∏(1−pᵢ)`**（独立相乘合成），其余合成方式仅作配置开关——**禁止把"武器半径取 max"口径套到探测概率**（系统性低估威胁）；**膨胀系数/衰减曲线/压制因子默认值见下方默认参数表** | 加法项（软）+ 穿越段概率约束 |
| 禁飞/限飞区 | 区间内 = 无穷代价 | 硬阈值（乘法掩码） |
| 蓝方武器压制 | 对雷达代价的**修正因子**（压制后探测距离缩短 → 代价缩小），非独立代价项 | 乘法修正 |

**无解出口顺序（硬性约束）**：FMM 传播结果中起点/终点不可达时，**不得直接报错**——按序执行：

1. **压制（仅当输入显式声明时启用，九轮共识，修正八轮"默认主模型"自相矛盾）**：压制（蓝方武器→红方探测距离缩短，乘法修正）**默认不生效**——输入未声明"该雷达被压制/压制常态"时，出口①**不得自动套用压制修正因子**（自动套用 = 输出纸面安全路径，实际飞行直接暴露）；仅当输入显式声明压制时启用，并按飞机探测概率参数放宽雷达代价；**主/回退语义**：压制（乘法修正）为主模型（仅显式声明压制时）、探测概率衰减为回退分支——若实际场景压制为常态（输入显式声明"压制常态"），则探测概率衰减模型转正为主模型；**未声明压制时出口①直接跳过**。
2. **探测概率穿越评估（十轮主管裁决：飞机可以穿越雷达探测区，但穿越的前提是必须考虑雷达探测概率）**：无解时启用探测概率模型重新评估——寻找穿越雷达探测区的低概率路径（穿越段累计探测概率 ≤ 阈值 P_cross，Phase 0 定值），找到则输出该路径（输出元数据携带"穿越雷达探测区"标记 + 穿越段探测概率度量，供下游签收）；**穿越评估不自动套用压制**（压制与穿越是两个独立手段）；**穿越路径同样须过全链复验（复验清单含探测概率计算），不允许"穿必标注"式静默交付纸面路径**。
3. **放宽目标范围**：`TargetZone.radius` 上限；**放宽界限由默认参数表中武器对应半径上限约束，超限即拒绝并显式告警**，防止静默交付超射程路径。
4. **走廊细分/重路由**：仍无解则执行。
5. **明确报错**：最终输出不可达原因。

**"无可用路径"判定标准（八轮共识，Phase 0 回填数值）**：出口顺序各步的触发/终止条件在 Phase 0 数据契约中量化——压制降权阈值 δ、探测概率衰减重算的迭代上限、半径放宽步长与上限、走廊细分轮次上限；未回填前不得声称"已实现需求 2 的无路径兜底语义"。

**粗细层往返收敛判据（十一轮共识）**："粗层可达 → 细层无解"是假阴性的主来源——重路由/走廊细分的触发条件显式化：**细层基元拟合成功率低于阈值（建议 90%，Phase 0 校准）或修复闭环（绕行 ≤3/重路由 ≤1）耗尽**时，判定"粗层走廊不可行"并触发重路由/走廊细分；收敛判据 = 细层成功率回到阈值以上或出口链耗尽（D7），**禁止无限粗细往返**（每次往返计入出口链预算，受降级链 ≤0.5s 约束）。

**出口④降级语义（四轮共识 + 七轮精度保证）**：超限后返回内容写死——按序取"最优可达点（距目标最近的合法位置）+ 显式原因"（不返回部分不可飞路径，也不静默丢弃）；**降级输出同样须过全链复验**（碰撞+机动+A4/A5，见 Phase 3），出口不得成为合规盲区。**降级输出精度保证（七轮主管裁决）**：求解过程**持续维护"当前最优合法候选"（warm best-so-far）**——每次产出新合法完整候选即与当前最优比较（目标达成度优先、次为代价），超时触发时直接输出该候选；**不得输出任意截断的中间状态、不得输出未过复验的部分路径、不得丢弃已有最优去重新搜索**。精度度量 = 合法性（零违规）+ 目标达成度（距发射阵位半径/目标距离）；降级输出精度不劣于"直接丢弃重算"的基线。Phase 0/2 验收用例：构造超时场景，断言输出 = 已知最优合法路径且 status=degraded_timeout。

**输出 status 契约（五轮共识 + 六轮边界补充 + 十轮原因码）**：最终出口输出 JSON 强制携带 `status` 字段——`success` / `degraded_timeout`（超时，资源性妥协，**超时触发后 ε 内必须返回**，不破坏预算） / `no_solution`（确定性无解）——**超时与无解必须分开**，下游处置完全不同；**`no_solution` 原因码区分（十轮共识）**：`geometric_unreachable`（几何/约束无解，确定性结论）/ `suppression_not_declared`（压制未声明且穿越评估后仍无解——提示下游可显式声明压制或调整雷达参数重跑；**不得自动重跑**，防纸面路径）；**非零退出只留给硬故障**（内存/IO 异常），不得用于超时/无解（对管道调用方"非零即崩溃"，会同时违约 B9）；**非法输入独立于 D1–D7（十三轮共识）**：`InputValidator` 前置独立模块——A=B、B 落在禁飞区内、雷达与禁飞区重叠、地形空洞残留、车辆参数不自洽（A6 已拦截的自洽类另走 fail-fast）等**退化输入**在进入算法前拦截，输出专属 status **`input_invalid`** + 原因码（区别于 `no_solution` 的确定性无解、区别于硬故障的非零退出；下游处置 = 修输入重跑）；**D1–D7 只覆盖"合法输入无解"，非法输入由校验层拦截**——"绝对不能崩溃"的入口防线（B9）；**降级结果消费规则**：下游对 `degraded_timeout` / `no_solution` 须**丢弃或重试，不得当作正常航路执行**。

**ε 边界归属表（六轮共识 + 七轮裁决）**：ε 为**相对量**（固定毫秒值在不同平台时钟粒度下破坏确定性，与 -ffp-contract=off 联动）——建议 `ε = max(1ms, 1% × 已用预算)`，上限 100ms；**边界归属**：`success`（3s 内完成且结果过全链复验）→ 达标；`degraded_timeout`（3s 后 ε 内返回**可用**结果，status 显式）→ 可接受降级（**七轮主管裁决：生产允许降级输出**），**不算达标**、也不违反 B9；超 ε 或无解 → 失败（`no_solution` 为确定性结论，不是失败）。**降级输出的可用性定义（七轮）**：`degraded_timeout` 的返回内容必须是**降级后最好版本**——当前已算出、过全链复验、质量最优的合法候选（warm best-so-far），且精度度量随输出一同声明，供下游签收判断。

**崩溃定义映射表（六轮共识）**：`非零退出 ≠ 崩溃`——崩溃 = panic/段错误/内存耗尽（进程异常终止）；非零退出 = 硬故障（IO/资源错误）或 fail-fast 校验拒绝（合法错误码，JSON 输出）；超时/无解不得触发非零退出。

**降级模式清单（九轮共识 + 八轮触发量化 + 十轮重排）**：可降级档位逐条编号——D1 `degraded_timeout`（超时返回 warm best-so-far，精度 = 降级后最好；**触发改确定性工作量预算（十轮共识）：节点扩展数/浮点运算计数耗尽，在基准硬件上校准使最坏墙钟≈3s，墙钟仅作最后保底——同输入两次运行触发时机一致，确定性不被机器负载破坏**）→ D2 `no_solution`（确定性无解，非失败；**携带原因码 geometric_unreachable / suppression_not_declared**）→ D3 出口①压制/降权（软约束放宽，仍输出合法路径，仅输入显式声明压制时可用）→ **D4 出口②探测概率穿越评估（十轮新增档：低概率穿越路径合法输出，带"穿越探测区"标记 + 探测概率度量，过全链复验）** → D5 出口③半径放宽（受武器上限约束）→ D6 出口④走廊细分/重路由 → **D7 终态（十轮共识）：全链耗尽 → `no_solution` + 原因码（D 档只列动作、终态只出一个，杜绝"动作与终态混排"语义错乱）**；**各档触发条件在 Phase 0 数据契约量化**（D1 触发 = 确定性预算耗尽 + ε（墙钟最后保底）；D2 触发 = 全出口链耗尽；D3–D6 触发阈值见无解出口顺序量化）；**统一降级表（八轮共识 + 十轮补状态码）**：数据缺数链（内置包缺瓦/出界/损坏，见 4.2.5）与 D1–D7 探测/性能链**合并为一张降级表**（数据缺数 → D2 `no_solution` + 原因码 DATA_MISSING；**地形数据文件缺失/不可读 → 启动期 fail-fast 硬故障 + 合法错误码 `terrain_unavailable`（十轮共识：数据层故障显式状态化，"绝对不能崩溃"不靠静默兜底）**；数据损坏 → 启动期 fail-fast 硬故障，不进降级表）——每次降级输出须带 `status` + 原因码 + 精度度量（目标达成度/代价），供下游签收判断；**崩溃（panic/段错误/OOM）不在降级清单内**（B9 零容忍）。**输出语义版本号（六轮共识）**：C11 输出 JSON 顶层携带 `schema_version` 字段——双基准 + 多轮迭代下验收口径可追溯，消费方按版本解析。

**出口预算（防超时护栏，端到端口径，十轮穿越档后更新）**：真正触发全场 FMM 重传播的只有出口①（压制）与**出口②（穿越评估：需以探测概率模型重估代价场）**；出口③放宽 TargetZone.radius **不触发重算**（传播场与终点半径无关，仅等值面查询），出口④为局部图上操作——**最坏 3×FMM 而非 2×**（Phase 0 实测确认穿越评估必须整场重跑还是可局部重算）。护栏：单次 FMM 预算 ≤0.5s（Phase 0 实测）、出口①降权阈值 δ 在数据契约中定义、出口③④ warm-start 复用上一场（CostFieldUpdater 局部重算）、**总耗时 3s 硬护栏以端到端为准（从启动到 stdout 输出可用航路结果集，六轮主管裁决）**：超时直接走 D7 终态快速失败，绝不无限循环；**不做每过程精细子预算**（六轮主管裁决），5.1 的环节占比仅为初始分配参考，验收只看端到端；**降级链预算（九轮共识 + 十轮扩展）**：降级链 D1–D7 各步自身也耗时间，须分配**主算法预算 + 降级链预算**（建议初始分配：主算法 ≤2.5s + 降级链 ≤0.5s，Phase 0 实测回填），出口链任一步不得无限执行——D 档任一步跑满降级链预算仍未收敛即快速失败走下一档，直至 D7 终态，总时长仍受 5.1 线性口径约束（100km ≤3s 典型值）。

**默认参数表（三轮共识，Phase 0 数据契约固定）**：避免"参数拍脑袋"导致表面覆盖、实现走样——以下默认参数在 Phase 0 数据契约中一次性固定，输入未提供时使用；**表中数值均为"占位值"，Phase 0 用真实场景核验校准后才生效（四轮共识）**：

#### 4.2.2 高程基准与高度语义

- **高程基准统一（按源识别，默认 EGM96）**：SRTM/HGT 原始高程为 EGM96 大地水准面参考；**GeoTIFF/DTED 的垂直基准随文件头/规范而定**（可能为 EGM2008/CGCS2000 似大地水准面等），与飞机几何/气压高度基准不同，山区差异可达数十米，直接违背"飞机不能撞山"。**统一规则**：解析层按格式头/规范识别各源原始垂直基准 → 经垂直基准层统一归一为椭球高 H（EGM96→WGS84 椭球面换算），路径搜索与碰撞校验只使用归一后高程；**未标注基准的源默认按 EGM96 处理并告警**；大地水准面模型数据来源（如 NGA EGM96 15′ / EGM2008）进 Phase 0 采购清单；Phase 0 数据契约固定换算参数与单测样例。**默认场景（无地形输入）**：DEM = 0（海拔 0 三维平面，见 4.2.4），AGL = H。
- **限飞区高度语义**：`RestrictedZone` 的 `[alt_min, alt_max]` 统一为**绝对海拔（MSL）**；输入若为离地高度（AGL，如"禁入地面以上 500m"），解析层须结合该区域地形高程换算为 MSL 后存储（AGL 语义下区间随地形起伏变化）。
- **限飞区垂直防吞没条款**：若以高度分层网格表达 FMM 代价场，层厚下界须 ≤ min(输入限飞区厚度)/2，且 cell 与限飞区区间相交即整层保守封禁（不采中心点）；细层/后处理保持连续高度校验兜底——杜绝薄限飞层（如 [100,300]m）被粗网格吞掉，需求 5 失效。**边界格点硬约束断言（八轮共识，安全项最高优先）**：粗层离散化（2km 水平 / 分层垂直）不得把"地面到无限高"硬边界或薄高度层抹成可穿越软代价——粗层软代价仅作收敛手段，**硬断言兜底**：边界相交格点一律保守封禁，且细层/后处理对粗层结果的任何放宽路径执行硬校验（禁飞/限飞包含），**边界格点断言 + 垂直分层粒度进 Phase 0 实测**（含 [100,300]m 薄层用例）。
- **限飞区 × 高度剖面仲裁规则（十轮共识）**：高度剖面独立插值不得静默撞限飞高度带——**高度剖面只在 [地形净空, 限飞区下界] 可行高度带内插值**（同时满足不撞山 ∧ 不越限飞区 ∧ 爬升角可行）；**可行带为空 → 该走廊段无解 → 触发走廊细分/重路由**（回退层已有），各约束不互让（不做"谁让谁"的隐式优先，杜绝"地形逼爬升撞限飞区"时静默改约束）。

#### 4.2.3 任务坐标系配置

坐标系不再是代码内部约定，而是**任务级配置**：输入 JSON `crs` 字段声明、内部自动推导计算面，**默认输入坐标系为 WGS 84**（零配置可用）。

| 项 | 规定 |
|----|------|
| **默认输入坐标系** | **WGS 84**（经纬度 + MSL 高程）；输入未声明 `crs` 时一律按此处理；**datum 转换策略（九轮共识）**：输入 `crs.datum` 与地形数据基准不一致时（如输入 CGCS2000、地形 SRTM=WGS84，差几十米），二选一写死——① 内置 3/7 参数 datum 转换（椭球参数表 + 开发期 WKT2 核对写入）② 或声明"仅接受 WGS84，其他 datum fail-fast 拒绝"；**当前默认：接受 WGS84 / CGCS2000（椭球参数表语义正确，二者差异厘米级），其余 datum 未声明转换规则时 fail-fast 拒绝** |
| 主算面 | 自定义 TM（中央经线 = 任务 AB 连线中点，k0 默认 1.0、参数化暴露 0.9996）；单任务规划半径 <150km 用自定义 TM，超界切标准 UTM/GK 带；**使用域：误差界按地面距离定义（与纬度基本无关），纬度 >84° 切 UPS 极地方位投影**；事后校验路径横向偏移 ≤ 半宽，超限重投影一次迭代；**几何口径钉死（十一轮共识）**：代价场/基元/转弯半径/环带等**一切距离计算定义在本地等距投影（自定义 TM/ENU）**，经纬度仅作 IO 存储——高纬经度间距收缩由投影层吸收；**"152.87m"分辨率语义（十一轮共识）**：SRTM 语义 = **等经纬度网格（弧秒制）**，5 弧秒仅在赤道 ≈152.87m、纬向随 cosφ 收缩；若按地面等距重采样则分辨率声明改为"地面等距"——**二选一在 Phase 0 钉死并写入数据契约元数据（见 4.2.5）** |
| 近场 ENU | ≤2km 机载局部框架（传感器融合/短距避撞/起降），与 IMU/惯导融合，纯旋转变换；不承担任何全局计算 |
| 垂直分量 | 坐标层统一存绝对椭球高 H；代价场用 AGL = H − DEM 高（高程差，实时求差）；垂直基准层可插拔（EGM96 默认 / EGM2008 / CGCS2000 似大地水准面），与投影插件同模式 |
| 多机协同 | 投影参数 + 椭球 + 垂直基准打包为**任务坐标系配置**全局下发，统一计算面、原点不逐机定义；增量/多任务沿用同基准，跨任务用任务 ID 隔离；**vehicles 数组多机共享同一任务坐标系（十三轮共识，见 4.2 多机输入契约）**，代价场缓存按源键共享 |
| 输出投影 | `forward/inverse` codec 插件：UTM（自动分带）/ GK 3°（CGCS2000）/ 经纬度 / 自定义 TM，仅 IO 边界转换一次，计算面不参与 |

**crs 参数字段（默认值，零配置可用）**：

```json
{
  "crs": {
    "datum": "WGS84",
    "vertical": "MSL",
    "input_projection": "lonlat"
  },
  "output_crs": { "projection": "lonlat" }
}
```

> `datum` 可选 WGS84 / CGCS2000 / GRS80（椭球参数表，语义正确而非精度刚需——三者差异厘米级）；`input_projection` 支持 lonlat / utm / gk3（输入本身是投影坐标时）；`output_crs.projection` 支持 lonlat / utm / gk3 / custom_tm。

**WKT2 定义文件（开发期辅助定义，内容写入项目）**：坐标基准与投影参数**不手抄、不猜**——开发时从 EPSG.io 下载以下 WKT2 定义文件，仅作**开发期参考**，核对后将其中的椭球与投影参数（a、f、k0、中央经线、假东/北等）**写入项目参数表（编译期常量）**；**WKT2 文件不随产品分发、用户不可见**；不引入 WKT2 解析库、不做任何运行时动态导入：

| CRS | EPSG | 用途 |
|-----|------|------|
| WGS 84 | 4326 | **默认输入坐标系**（经纬度基准）权威定义 |
| CGCS 2000 | 4490 | CGCS 2000 输入/输出（`crs.datum` 与 GK 3° 输出基准）权威定义 |
| WGS 84 / Pseudo-Mercator | 3857 | Web 墨卡托（地图瓦片/Web 可视化对接，`output_crs` 可选投影）权威定义 |

> 落地方式：开发期下载 WKT2 → 人工核对参数 → 写入 coord.rs 参数表（带来源注释与日期）→ 用已知坐标回代单测校验投影结果（如北京/上海已知经纬度→UTM/GK 值对照，CI 断言）；WKT2 文件仅留在开发环境作审计参考，不进入交付物。

#### 4.2.4 默认场景（海拔 0 三维平面）

**默认场景定义**：无地形数据输入时，任务空间为**海拔高度 0 的三维平面**——DEM 一律为 0，无地形起伏；零配置即用（与默认输入坐标系 WGS 84 同级）。

| 影响面 | 默认场景行为 |
|--------|------------|
| 地形代价 | 地形项全 0：无硬不可达（撞山）、无软代价（近地/坡度）——代价场仅由雷达 + 禁飞/限飞区构成 |
| 地形遮蔽 | 默认不生效：无地形文件时**防撞与地形掩护（LOS）均不考虑**（无山可撞，也无地形遮挡雷达，六轮主管裁决）；**遮蔽计算依赖地形数据文件存在（十轮主管裁决确认）**：遮蔽 = 三维射线求交（雷达视线是否被山体遮挡），无 DEM 数据源时该计算不存在——非策略关闭而是数据不可用，有地形文件时自动具备计算前提（LOS 条件启用见 4.3）；"地理遮蔽提供通道 / 地形掩护规避探测"仅在输入真实地形数据时成立 |
| 高度语义 | AGL = H − DEM = H − 0 = H：MSL 高度即离地高度；限飞区 MSL 语义不变（见 4.2.2） |
| 输入地形数据 | 有地形（SRTM/GeoTIFF/DTED/内置数据包）时按 4.2.2 归一化后使用，默认场景自动退出 |
| Phase 0 基准 | 默认平面场景作为**最小基准**（零障碍直航/单雷达，仅验证管线正确性）；**3s/百公里达标判定必须以"真实 SRTM + 多雷达负载"场景为准**（Phase 0 步骤 6），默认平面达标不算数（四轮共识） |
| 已知限制声明（五轮共识） | **默认场景不验证 A7"地理遮蔽提供通道"路径**——遮蔽=0 使该特性默认关闭，须在带真实地形 + **遮蔽>0 用例**中验收（见 5.2 双基准）；降级分支须有**可观测性钩子**（指标/日志），证明其被真实触发过 |

> 定位：默认场景保证"零配置可用"与最小可验证基线；真实地形是显式输入，不是默认。

#### 4.2.5 内置地形数据契约

**主管裁决（八轮 + 九轮）**：
- **数据源二选一——只会提供一份**（九轮主管裁决）：交付时主管**仅提供一份**内置数据包，二选一：**全球 152.87m（≈5 弧秒）原始约 8GB** 或 **中国范围 76.44m（≈2.5 弧秒）原始约 1.53G**；**保留切换可能**——未来改供另一份时，替换 data 文件即可，运行时**单一数据源**（原 v0.11"多源叠加/跨包接缝一致性"自然失效，无需融合）
- **离线文件交付（接受）**，我方不联网下载

**压缩链路（GDAL 开发期预处理 → 自建紧凑格式）**：输入为主管提供的原始未压缩数据（GeoTIFF 或原始网格）→ GDAL（开发期离线工具，见 3.2.1）做垂直基准归一/填洞/裁剪 → 转**自建紧凑格式**：16-bit 有符号高度 + 经纬度范围头（min/max lat/lon、行列数、分辨率、垂直基准、来源元数据）+ **分块（256×256）内差分预测 + Zstd 压缩**（压缩在**开发期由 zstd CLI 完成**；运行时用 **`ruzstd`（纯 Rust 解码器）** 解码，零 C 依赖，见 3.2.1 红线）；支持**按需解压/流式读取**（块 LRU 缓存，与 5.1 瓦片策略同构），运行时内存可控。

**体积目标（二选一档位）**：

| 数据包（二选一） | 原始 | 压缩目标 | 判定 |
|--------|------|---------|------|
| 全球 152.87m | 8GB | **≤800MB（目标），上限 ≤1.3GB** | 内置上限档 |
| 中国 76.44m | 1.53GB | **≤400MB（目标）** | 内置 |

**内置体积判定规则**：压缩后 ≤300MB 理想 / ≤800MB 上限 / >800MB 一律**外置**（数据文件随发布附带，不打进二进制；二进制保持小体积）。**压缩率实测门（九轮共识）**：8GB→800MB（≈10:1）是未经验证的压缩率承诺——Phase 0 用**高频噪声区代表性瓦片**实测压缩率与解压吞吐，断言 ≤800MB（全球）/ ≤400MB（中国）；实测超限触发外置判定或回主管协商数据策略，**不得留到交付期**。

**切换与使用（九轮主管裁决：二选一）**：
- 交付含**一份**数据包（`data/terrain.zstd`，来源按主管提供：全球或中国）；切换 = 替换数据文件 + 配置声明，无需改代码
- 无跨包接缝问题（不存在双包共存）；**缺数/极区降级（九轮共识）**：单源缺瓦/出界一律按 `no_solution` + 显式告警（见 4.5）——若为全球包且数据源仅覆盖 56°N–60°S（SRTM 系），高纬任务出覆盖范围即缺数，须在入库校验时记录实际覆盖边界并随元数据声明；若为中国包，任务须在中国范围 + 边距 ≥10km 内，出界即 `no_solution`
- **版本锁定 + 哈希校验 + 启动期 fail-fast（八轮共识，数据安全最高优先）**：数据包元数据强制携带 `data_version`（随包发布，含格式版本 + 数据版本）；随包发布 SHA-256 清单（`terrain.zstd.sha256`），启动时校验文件哈希与元数据版本——**校验失败 = 硬故障（非零退出 + 合法错误码），禁止静默降级**（错路径比崩溃更危险：静默用错数据会产出合法外观的错误航路）；**data 与二进制版本不匹配时同样 fail-fast**（格式版本检查在解包前完成，杜绝"旧二进制读新格式/新二进制读旧格式"的隐性错读）

**数据要求**：

| 项 | 要求 |
|----|------|
| 数据来源 | 真实地形原始数据（非合成/虚构）；元数据声明来源与生成方式 |
| 分发形态 | **离线文件交付（接受）**：主管直接提供（zip 或目录）；入库路径 + 校验脚本交付（见 5.2 双基准） |
| 版本与校验（八轮共识） | 数据包元数据携带 `data_version`（格式版本 + 数据版本）；随包 SHA-256 清单（`terrain.zstd.sha256`）；启动期哈希 + 版本校验，失败 = 硬故障 fail-fast（禁止静默降级，见 4.2.5 切换与使用） |
| 分辨率 | 全球 152.87m（≈5 弧秒）或 中国 76.44m（≈2.5 弧秒），二选一；可接受 1–10 弧秒范围（>10 弧秒即 >305m 拒绝：FMM 粗层 1–2km 网格 + 裕度条款下不足以保证 100km 级任务）；**"152.87m"语义钉死（十一轮共识）**：等经纬度（弧秒制）语义（赤道≈152.87m，纬向随 cosφ 收缩），代价场距离计算一律经本地等距投影（见 4.2.3），不直接用经纬度差算距离；若改供地面等距重采样数据须在元数据显式声明"地面等距"；**z 分辨率定稿（十三轮共识）**：垂直分层统一 **50m 固定层高**（见 4.2 网格维度定稿），写入数据契约元数据（`z_resolution_m: 50`），限飞区高度吸附最近层 |
| 覆盖范围 | 按主管提供的数据包实际声明（全球包记录实际纬度覆盖——SRTM 系仅 56°N–60°S；中国包 = 中国区域 + 边距 ≥10km）；瓦片组织按数据源声明，元数据记录 |
| 垂直基准 | 元数据声明；SRTM 系默认 EGM96，其他源按 4.2.2 按源识别归一为椭球高 |
| 空洞处理 | 交付数据**不得含无效值**：空洞须已填；若残留无效值按 4.2.2 邻近插值兜底 + 告警 |
| 元数据 | 随数据提供 README/清单：来源、分辨率、垂直基准、覆盖范围（含实际边界）、生成日期 |
| 入库校验 | 校验脚本断言：格式/分辨率/覆盖/空洞/元数据齐全 + **压缩率实测门**（含高频噪声区瓦片）+ **覆盖边界记录**；缺瓦/出界按 `no_solution`（见 4.5） |

> 与完整精度输入的关系：完整精度地形（用户任务输入）仍走 4.2.2 归一化后使用；内置数据为**交付基准默认数据源与经纬度匹配兜底**（C10"经纬度匹配"），两者共享 `TerrainSource` trait，不新增解析路径。

### 4.3 架构扩展点（trait 化预留）

| 扩展点 | 设计 |
|--------|------|
| 地形数据源 | `TerrainSource` trait（`height_at(lon,lat)` / `query_along_segment`），实现：SRTM/HGT（自研 `.hgt`）、**GeoTIFF（`geotiff`）**、**DTED/DTED2（`dted2`）**、**自建紧凑格式（16-bit + 分块差分 + Zstd，内置数据主实现）**——均运行时、发布版必含；**内置数据单源（九轮主管裁决：二选一只提供一份）**：数据文件决定源，配置声明即可切换，无多源叠加（见 4.2.5）；按输入文件扩展名/魔数自动选择 reader |
| 雷达模型 | **默认球形模型（保守探测范围上界）**，经 `ThreatModel` trait 抽象，**保留载入外部雷达模型的接口和能力**（默认实现为球体，外部模型按接口接入，第一版不强制实现）；**探测概率为必选接口（十轮主管裁决）**：`ThreatModel` 必须提供 `detection_probability_at(point, exposure_time)`（随距离衰减 + 暴露时间相关），穿越探测区的路径以累计探测概率评估（阈值 P_cross，见 4.2.1），探测概率从"回退分支"升级为必选模型；**多雷达重叠区合成（十二轮共识）**：`ThreatModel` 对重叠区按概率并集 `1−∏(1−pᵢ)` 合成（探测概率档），默认球体口径保持覆盖 max（保守）——禁止套"武器半径取 max"口径到探测概率；隐蔽突防用**飞机的探测概率参数**（`VehicleProfile.detection_probability`）折算；蓝方武器压制保留为无解出口①修正因子（仅显式声明启用）；**地形掩护（LOS）条件启用（六轮主管裁决 + 十轮数据依赖确认 + 十二轮硬 mask 语义定稿，修正十一轮"收益项"表述）**：**遮蔽计算以地形数据文件存在为前提（十轮主管裁决）**——有地形数据文件时，山体遮挡雷达视线产生遮蔽区，航路可借地形掩护规避探测；**LOS 遮蔽定义为探测概率的硬 mask 乘子（十二轮共识）**：`p_det(point) = f_distance(r, t_exposure) × mask_LOS(point)`——**不是带权重的收益项**：LOS 只做探测概率的乘性修正，**不需要权重标定**；**球体保守口径 = mask≡1 特例**（LOS 关闭时退化为原球体模型，两口径从"打架"变"分层"）；LOS 启用时遮蔽区探测概率乘 mask 系数（默认 0.05–0.1，守保守口径、不取 0——低估威胁比绕路更危险）；**求解与复验强制同一档位**（粗层 FMM 与细层复验用同一 mask 函数，防"粗层判遮蔽、细层判漏光"打架）；**粗层只做候选排除、细层 152.87m 复验为终判**（±1 格容差）；避撞（防撞山，硬约束）走地形净空，LOS mask（利用掩护，探测概率修正）与避撞共用线段-地形射线求交能力（`query_along_segment`），不新增重型几何；**LOS mask 预计算预算归属（十三轮共识，见 5.1）**：分辨率同粗层（1-2km，非细层）、传播前一次性预计算 + 缓存（warm-start 复用）、计入 3s 预算单列预计算项（建议 ≤0.5s，Phase 0 实测），预计算超时走降级链；**无地形数据文件时不存在该计算**（退化为平面几何，与 4.2.4 默认场景一致） |
| 路径平滑器 | 策略链：`Dubins → 样条 → 抽稀`，各环节独立可替换（trait） |
| 多段路径拼接 | 路径状态空间预留"多段拼接"接口（A→武器投放区→撤退），武器投放区作为中间必经航路点类型，不写成单次 A→B |
| 代价场更新 | `CostFieldUpdater` 抽象（威胁参数→场重算），实现层 FMM 整场重跑（O(NlogN)）或分层局部重算可插拔；为未来动态威胁预留，**不预埋增量搜索算法**（D\* Lite 已排除，见 4.4） |

### 4.4 算法选型决策记录

| 算法 | 结论 | 理由 |
|------|------|------|
| 均匀网格 A\*（旧方案） | ❌ 淘汰 | 离散化与运动学失配：锯齿、转弯半径无法表达、状态爆炸 O(N³)、启发式在强非平滑代价场退化 |
| A\* 家族（细层/回退层） | ✅ 保留 | A\* 是图搜索与维度无关；细层运动基元搜索、回退层拓扑路由仍是正确工具 |
| FMM（粗层） | ✅ 定案主方案 | 单次传播全可达域、多机共享、确定性、O(NlogN)、地形天然进代价函数 |
| RRT / RRT\* / PRM | ❌ 排除 | 采样质量无界，确定性难满足 3s 硬指标 |
| D\* / D\* Lite | ❌ 排除 | 静态单查询无增量场景；**强非平滑代价场（禁飞区硬边界/雷达尖峰）下增量传播退化为近全量重搜**；与 FMM"全场传播"模型语义冲突；实现复杂度高（LPA\* 全家桶）；HashMap 迭代序还有确定性隐患（可用 BTreeMap 规避，但非主因） |
| Hybrid A\* / Lattice | ⚠️ 细层候选 | 运动学可行、确定性好，与运动基元搜索本质一致（Lattice 是基元预生成的工程化形态），细层实现择一 |
| Theta\* | ✅ 后处理辅助 | 几乎零成本消除锯齿 |
| GDAL（运行时） | ❌ 排除 | 重型 C++ 依赖（PROJ/GEOS/libpng/curl 等十余 C 库），破坏 musl 静态单二进制；运行时仅需"读高度+射线求交"，自研几十行即可 |
| GDAL（开发期） | ✅ 定位为离线预处理工具 | 任意格式 DEM → 重采样/裁剪/填洞 → 导出自建格式；**运行时地形读取全用纯 Rust crate：`geotiff`（GeoTIFF）/ `dted2`（DTED）/ 自研（SRTM-HGT）**；GDAL 仅在高阶处理（重投影/填洞）时本地手动使用 |

**未来动态威胁的正确准备（不预埋 D\* Lite）**：
- **时间维 out-of-scope（四轮共识）**：第一版为**静态筹划**——雷达开机/压制时间窗不建模，需求未出现时间维输入，写明此假设即闭环；多时相威胁（威胁时间窗/航线时段）留未来
- 抽象「代价场更新」接口（威胁参数→场重算），实现层 FMM 整跑或局部重算任选，D\* Lite 只是其中一种实现且非最优，不预先绑定

## 五、性能预算与验证策略

### 5.1 性能预算分解（3s / 100km，端到端口径）

> **验收口径（六轮主管裁决 + 九轮线性外推 + 十轮复杂度前提）**：`每百公里 ≤ 3s` 为**典型值（九轮主管裁决）**——验收基准 = **100km 航路的计算时长 ≤3s**（从进程启动到 stdout 输出可用结果集的端到端 wall-clock）；**航程按比例线性外推，无隐藏封顶**：300km ≤9s、1000km ≤30s；**线性外推的复杂度前提（十轮共识）**：FMM 沿 **A–B 走廊窄带传播，带宽不随距离增长**——搜索空间体积 ∝ 距离（而非 ∝ 面积/体积）；此声明写入复杂度论证与 Phase 0 基准（测 100/300/1000km 三档，验证体积-时间关系近似线性，不达标则 3s 口径降格为"基准场景语句"并回主管重定验收口径）；**远距离情况下每过程精细计算无意义**，不做每过程精细子预算；下表占比仅为**初始分配参考**（Phase 0 benchmark 校准），**验收只看端到端**；**降级链预算（九轮共识 + 十轮扩展）**：主算法 ≤2.5s + 降级链 ≤0.5s（建议初始分配，Phase 0 实测回填），出口链任一步不得无限执行（见 4.2.1）；**分层预算分解（十一轮共识）**：预算按架构三层分解——**粗层 FMM 传播 / 细层运动基元搜索 / 后处理平滑-抽稀-复验**——每层分配独立预算占比（下表拆分），**防止"细层饿死"**（粗层占满预算、细层搜索零余量导致假阴性）；占比仍为初始分配参考，Phase 0 benchmark 按三层分别计时回填，**验收仍只看端到端**（六轮裁决不推翻，分层分解仅为预算兜底与调优手段）。

| 环节 | 预算占比（建议初始分配） | 说明 |
|------|------------------------|------|
| 雷达/禁飞区碰撞与邻域查询 | ~30% | rstar 空间索引加速 |
| 地形遮蔽求交 | ~40% | 射线-地形查询，LOD/降采样策略兜底；**无地形文件时该环节为 0**（六轮裁决：防撞/LOS 均依赖地形文件存在）；**LOS mask 预计算预算归属（十三轮共识）**：启用 LOS 时 mask 场（分辨率同粗层 1-2km，非细层）在传播前**一次性预计算 + 缓存**（warm-start 复用），**计入 3s 预算、单列预计算项**（建议 ≤0.5s，Phase 0 实测回填），预计算超时同样走降级链——LOS 预计算不得逃逸出预算 |
| FMM 粗层传播（窄带） | ~15% | 走廊窄带传播，带宽不随距离增长（十轮共识）；多机共享同一传播场（摊薄成本）；**N 机端到端总预算 = Σ 各机每百公里预算，共享传播部分摊薄不重复计（十三轮共识，见 4.2 多机输入契约）** |
| 细层运动基元搜索 | ~10% | 基元拟合/搜索，走廊剪枝控制节点数；**预算显式分配（十一轮共识），防"细层饿死"** |
| 平滑/抽稀/复验等后处理 | ~5% | 线性的，量级小；**含二次碰撞校验与修复闭环**（复验清单见 Phase 3） |

**修复链预算（四轮共识）**：后处理-校验-修复链为独立预算项——局部绕行 ≤N 次（默认 3）+ 重路由 ≤1 次计入总 3s 护栏；重路由（全量 FMM 重跑）最坏 1 次 + 出口⑤快速失败，余量写入总预算，杜绝迭代无上界。

**GeoTIFF 运行时性能形态**：GeoTIFF 是压缩瓦片格式（LZW/Deflate），逐点查询需解压瓦片，比 SRTM 裸网格慢 1-2 个数量级。`GeoTiffSource` 采用两级策略：小范围（少于阈值瓦片）加载时全量解压为内存网格（等同 SRTM 常驻）；大范围走**瓦片 LRU 缓存 + 多分辨率 Overview**，保证地形求交预算（~40%）不被单次解压击穿。Phase 0 需补 GeoTIFF 读取基准。

**DTED/DTED2 运行时性能形态**：DTED 是**无压缩**裸高度数据（16-bit + 行校验），读取性能接近 SRTM（内存常驻/顺序读即可），不需要 GeoTIFF 的瓦片解压策略；`dted2` 的 `get_elevation(lat,lon)` 直接匹配 `TerrainSource` 接口，Phase 0 一并纳入地形基准。

**内置紧凑格式（自建）运行时性能形态**：分块（256×256）差分 + Zstd 压缩，运行时 `ruzstd` 按块解压 + LRU 缓存（与 GeoTIFF 瓦片策略同构）；**解压 + 按需 I/O 耗时计入地形求交预算（~40%）**（九轮共识）；Phase 0 用实际内置数据基准（压缩率 + 解压吞吐），**压缩率实测门**验证 8GB→≤800MB / 1.53G→≤400MB 承诺（含高频噪声区瓦片，见 4.2.5）。**数据加载 + 解压单列基准（八轮共识）**：启动期一次性解压/索引构建（非按需 I/O）在 5.1 预算中**单列落账**——`t_load_decompress`（800MB 包全量读入 + 索引构建，不含算法计算）作为独立基准项，目标 ≤300ms（Phase 0 实测回填）；**3s 基准硬件规格声明（八轮共识）**：所有端到端 3s 基准必须随结果声明运行硬件（CPU 型号/核心数/内存/存储类型），跨硬件复现时按规格换算——不声明硬件的 3s 数字不可验收、不可对比。

> 实际分配以 benchmark 数据为准，**所有"自研 vs 引库"决策以性能数据为依据**。

### 5.2 验证策略

- **单元测试**：几何/坐标/地形/算法各模块（沿用旧项目 22 测试的覆盖思路）
- **基准测试**：`criterion`（或简单 bench 脚本）对四大耗时环节（**FMM 粗层全量传播**、雷达索引、地形求交、细层运动基元搜索）单独 benchmark；**FMM 全量传播耗时（O(NlogN) 实际常数）同时决定未来动态威胁时"整跑重规划 vs 分层局部重规划"的取舍，并顺带验证确定性硬指标**
- **端到端回归**：标准场景集（零障碍直航、单雷达、100km+3 雷达直线/错位、带地形 100km）持续回归，3s 预算一票否决；细层走廊内 100 组随机起止，量化拟合成功率与单段耗时
- **复验采样密度与独立性（九轮共识）**：后处理二次校验的采样须为**段内最坏情况**——每段采样 = 端点 + 中点 + 按地形网格间距保守加密（内置包 152.87m 下，段内小山脊可能完全落采样盲区）；**复验器与求解器数据路径/代码路径分离**：求解走走廊+基元（粗层）、复验走全分辨率逐段采样（独立校验路径，不共享求解器几何代码），杜绝"自己查自己"掩盖系统误差；校验用地形精度与搜索用地形精度一并写入验收记录（低精度包校验须声明误差上界，超限触发安全裕度条款）；**复验清单显式化（十轮共识 + 十二轮 A6）**：`{弦高（几何逼近误差）} ∪ {转弯半径（曲率）/ 转弯角（航向变化）/ 航向连续性（抽稀删点后相邻段连接处）} ∪ {终端包线（航向/高度/速度，若终端 pose 下放平滑级）} ∪ {地形净空} ∪ {穿越段累计探测概率（若含穿越雷达探测区）} ∪ {A6 速度-转弯半径物理自洽（r_min ≥ v²/(g·tan φ_max)，十二轮共识）}`——**防止"弦高复验"被当成抽稀后唯一复验而挤掉机动/包线检查**；**复验盲区声明（十轮共识 + 十一轮粒度钉死）**：仅内置低精度数据时，系统性误差（152.87m 抹平窄通道/漏峡谷）不在复验保证范围——通道保留率作为数据层验收（见 Phase 0 步骤 6），不得宣称"绝对不撞山"强于数据分辨率；**LOS 复验粒度（十一轮共识）**：遮蔽/LOS 复验显式钉为**航段级**——对最终航迹**逐航段**做全分辨率射线求交（非节点级抽样：节点通过 ≠ 航段通过，航段中段穿山脊是节点级漏检区），采样密度按段内最坏情况；**网格撞山边界（十一轮共识）**："不能撞山"的保证边界 = 数据分辨率内（格点采样 + 净空裕度），窄于网格的通道/峰顶由通道保留率数据层验收兜底，不宣称强于分辨率
- **确定性回归**：相同种子输出逐位一致（跨平台 CI 验证）；**浮点确定性约定（四轮共识 + 六轮补强 + 八轮归约顺序）**：编译期 IEEE754 严格语义 + 禁用 fast-math 类优化（`-C target-cpu` 不引入快速数学标志）+ **显式禁 FMA 收缩（`-C target-feature=-fma` 或 `-ffp-contract=off` 等价配置）** + **固定编译目标/CPU 特性集**（release 构建锁 target-cpu 与 target-feature，防 LLVM 自动向量化/FMA 引入跨平台位差），跨平台复现范围显式声明；**rayon 归约顺序写死（八轮共识）**：所有并行归约（代价场求和、多雷达 max、走廊统计）**固定分块/归约顺序**（如 `rayon::reduce` 配合固定索引分块而非 `fold` 无序合并），并行化不得改变逐位结果——基准结果须带**并行开关对照**（同输入串行 vs 并行逐位一致）；**确定性可执行化三条（十三轮共识，把"逐位复现"从声明变热路径硬规范）**：① **热路径禁无序迭代**——HashMap 遍历序不定，热路径（代价场聚合/雷达查询/走廊统计/多雷达 max 合成）一律 BTreeMap/排序索引，迭代序与插入序无关；② **确定性归约**——并行固定索引分块 reduce，禁止 `fold` 无序合并（八轮已写，十三轮升级为热路径硬规范，代码评审项）；③ **"两跑一致"回归测试**——同输入同机器连续两次运行逐位一致 + CI 断言（串行 vs 并行对照并入），入端到端回归用例集；ε 为相对量（与时钟粒度联动，见 4.2.1）
- **双基准验收（五轮共识 + 七/八/九轮主管裁决）**：3s/百公里验收同时绑定 ①**法定基准：真实 SRTM + 多雷达负载**（3s 硬护栏）②**交付基准：主管提供的内置地形数据包**（全球 152.87m 或 中国 76.44m，**二选一只提供一份**，数据契约见 4.2.5；更快是加分项）——交付**可复跑脚本 + 基准数据集入库**，一条命令双基准全过才算验收通过；验收矩阵至少含一个**遮蔽>0 用例**（验证 A7 通道路径，默认场景不验，见 4.2.4）；**端到端口径**：双基准均按"启动→可用结果集输出"测量（六轮主管裁决）；**双基准覆盖度裁决（八轮共识）**：① 法定基准 SRTM 为**真值**，交付基准（内置压缩包）须证明**覆盖度等价**——在典型遮蔽地形（山脊/峡谷/窄通道）对照 SRTM 与内置包求解，路径集（走廊/可选航路）一致率与 A7"遮蔽提供通道"保留率 ≥ 阈值（Phase 0 回填），内置包解压后高程相对 SRTM 误差 ≤ 压缩格式容许差（16-bit 差分量化误差，Phase 0 实测）② 内置包**哈希/元数据一致性**作为验收前置（sha256 匹配 + data_version 匹配，见 4.2.5）③ **A7 容差写死**：内置包"遮蔽>0 用例"的通道保留率容差在 Phase 0 定值入验收脚本（未定值不得声称 A7 达标）；**端到端假阴性率验收口径（十一轮共识 + 十二轮成对评估）**：定义"粗层可达但最终 `no_solution`"为假阴性（FNR）、"粗层不可达但实为可解"为假阳性（FPR）——**FNR/FPR 成对评估（十二轮共识）**：FNR（"有解误判无解"）设**一票否决级权重优先**（比假阴性更致命，呼应需求8：宁给合法路径勿误报无解），FPR 由降级链吸收（可用性损失，容忍上限 Phase 0 定）；**测量基建（十二轮共识）**：基准场景集（合成场景种子扫描：随机地形/雷达布防参数化生成 + 固定种子库，fuzz 边界验收已有基础）+ 统计口径（样本量/真值集/置信区间；**真值来源分层（十三轮共识，成对评估缺真值即不可执行）**：自动层 = 细网格/高分辨率重算结果作真值（冒烟与回归用，可批量生成）；人工层 = 小样本人工标注集（验收用，防自动层"自证清白"的系统性偏差）——两层互补，缺真值集时数字验收不可执行）入 Phase 0 契约——**"≤5%"降级为测量口径而非硬指标**；超限判定粗细层切换判据失效并回调（细层基元密度/走廊宽度）；假阴性率与粗细层收敛判据（见 4.2.1）联动验收
- **"好路径"量化验收指标（九轮共识 + 八轮口径定案 + 九轮区域语义）**：输出质量按三指标量化并断言——① 合法性（零违规：不撞山/不越禁飞限飞/机动约束全过）② 目标达成度（**进入发射阵位区域**——区域包含判定 + 发射包线，非点距离；区域为圆形时按 `TargetZone.radius` 判定，见 4.2 任务语义）③ 平滑度/抽稀度（中间点密度上限 + **每段弦高容差**，见 Phase 3 链序修正）；**穿越雷达探测区验收（十轮主管裁决）**：构造"雷达布防致几何无解"场景，断言输出含"穿越探测区"标记 + 穿越段累计探测概率 ≤ P_cross + 全链复验通过；构造"压制未声明"场景，断言 `no_solution` + 原因码 `suppression_not_declared`（区别于 `geometric_unreachable`）；**目标达成度 ↔ 判定半径口径先定（八轮共识 + 九轮区域语义）**：目标达成度的判定基准 = **输出路径终点进入发射阵位区域**（区域包含 + 发射包线校验；圆形阵位时 = 终点距阵位中心 ≤ `TargetZone.radius`）——判定基准先于一切优化定死，目标达成度计算与判定用同一基准，禁止"计算用 A、判定用 B"的口径漂移；**代价场末端放松后置（八轮共识，限定范围）**：允许对代价场做末端（进入判定半径后）放松以改善终端到达性，但**放松仅限末端有限半径范围内（≤ 判定半径 × 系数，Phase 0 定），放松后仍须过全链复验**，不得借放松绕过禁飞限飞或机动约束；**降级质量基线（九轮共识 + 十轮档位扩展）**：三指标同时作为 D1–D7 降级输出的质量基线——每次降级输出除 `status` + 原因码外，须随附三指标度量，与 4.2.1 降级输出精度度量合并口径，供下游签收判断；三指标随 status 输出，Phase 0 建立测试集与回归基线，作为"需求达标"判定依据
- **验收冲突仲裁优先级（六轮共识）**：同一场景多指标冲突时按序裁决——① 绝对不能崩溃（B9，panic/段错误零容忍，硬故障走合法错误码）→ ② 确定性（跨平台逐位一致，复现承诺优先于性能优化）→ ③ 3s 端到端（B8，超时走 `degraded_timeout` + ε 返回，不算达标但合法）→ ④ 输出质量（status 语义/复验合规）。任一冲突不得以"牺牲崩溃安全"或"牺牲确定性"换取性能
- **输出语义版本号**：C11 输出 JSON 顶层携带 `schema_version`，双基准 + 多轮迭代下验收口径可追溯（六轮共识，见 4.2.1）
- **输入边界 fuzz（四轮共识，B9 兜底）**：对 JSON 契约做边界/畸形输入 fuzz（空字段、非法经纬度、超界半径、缺失 crs/起终点、未知武器类型等），断言不崩溃、输出合法错误码；**退化输入用例（十三轮共识，InputValidator 验收直接可取）**：A=B、B 在禁飞区内、雷达∩禁飞区重叠、地形空洞残留、vehicles 数组为空/参数不自洽——断言输出专属 status `input_invalid` + 原因码，不进入算法、不崩溃；**崩溃测试套件（十四轮终裁新增，B9 显式验收项——"绝对不能崩溃"必须有可验证抓手，不测等于没承诺）**：退化/边界输入全集（fuzz 种子 + 十三轮退化输入全集 + 未知武器/畸形 JSON/超界字段）断言**进程不 panic / 不段错误 / 不 OOM**（崩溃定义 = panic/段错误/内存耗尽，见 4.2.1；合法处置 = 合法错误码 + JSON 输出），崩溃测试套件入 CI **一票否决**（任何 panic 用例 = 验收失败）
- **静态编译回归**：`cargo tree -e normal` 断言零 C 依赖（openblas/zlib/curl/proj/gdal/pcre/ssl 零匹配）+ `x86_64-unknown-linux-musl` release 构建通过，CI 一票否决（红线见 3.2.1）

## 六、实施路线

### Phase 0 — 性能原型与算法验证（第一步，最高优先级）

验证"性能与算法是否可达"，所有后续决策的依据：

0. **数据入库与压缩率实测门（九轮共识 + 八轮补强）**：对主管提供的原始数据包做 GDAL 预处理 + 自建紧凑格式压缩，**用高频噪声区代表性瓦片实测压缩率与解压吞吐**，断言 ≤800MB（全球）/ ≤400MB（中国）；实测超限触发外置判定或回主管协商数据策略；同时记录覆盖边界（极区/中国范围）供缺数降级使用（见 4.2.5）；**数据加载 + 解压单列基准**：`t_load_decompress`（800MB 包全量读入 + 索引构建）落账，目标 ≤300ms（见 5.1）；**启动期 fail-fast 校验用例**：构造"哈希不符 / 版本不符 / 文件截断"三用例，断言启动即硬故障（非零退出 + 合法错误码），**不得静默降级**
1. **性能预算分解为可测项**
2. **FMM 粗层基准**：100km 场景粗网格传播地形+雷达代价场，100 组随机起止，测单次传播耗时 + 走廊生成质量 + O(NlogN) 实际常数
3. **代价场复用验证**：同一传播服务 10 架飞机 vs 每机独立搜索，对比总耗时与内存（决定架构形态 → **落多机输入契约（十三轮共识，见 4.2）**：一次 FMM 传播多目标回溯 + 缓存按源键共享 + 3s 预算按机线性）
4. **rstar 雷达索引（N=100 雷达）基准测试**
5. **单条射线-地形求交（1000 采样点）基准测试**
6. **细层闭环**：FMM 出走廊后，走廊内 100 组随机起止跑 Dubins 拟合，量化拟合成功率与单段耗时，对照 3s 预算（**带真实 SRTM + 多雷达负载同时跑**，避免"虚假达标"）——**拟合成功率即粗细层收敛判据基准（十一轮共识）**，低于阈值（建议 90%）触发重路由/走廊细分参数回调；**假阴性率测量基建（十二轮共识）**：Phase 0 建立基准场景集（合成场景种子扫描），统计口径 = FNR / FPR **成对上报**，真值集 = 已知可解场景人工标注或高分辨率对照（**真值来源分层见 5.2**），置信区间与样本量写入验收记录；**补"地形+爬升角+转弯角联合约束满足率"验收项**——对每段平滑后航迹校验"不撞山 ∧ 爬升角≤上限 ∧ 逐段转角≤θ_max"联合满足率（针对 2D Dubins+独立高程插值的解耦风险，见 7 风险表）；**补 2D Dubins 水平基元 + 高程剖面联合用例**：显式定义水平基元所在高度层，量化 **"钻山率"**——真实 SRTM 下平滑航迹撞山比例；**通道保留率验证（九轮共识 + 八轮口径定案）**：用**实际提供的内置数据包**（二选一：全球 152.87m 或 中国 76.44m）在典型遮蔽地形验证"地形遮蔽提供通道"（A7）保留率——量化网格分辨率对窄通道的抹平影响；**口径 = 运动学可行通道（八轮共识）**：保留率按"基元可实际拟合出合法航段的通道"计数（几何可通行但运动基元拟合不出 = 通道丢失），与 4.2 运动学约束前置口径一致；**补边界格点硬断言用例**：构造"禁飞区边界斜穿粗格 / 薄限飞层 [100,300]m / 地形尖峰穿山"三用例，断言粗层软化不产生可穿越漏口（细层硬校验兜底，见 4.2.1 限飞区垂直防吞没条款）
7. **任一环节超标 → 降网格分辨率 / FMM 窄带实现 / 调整空间索引或地形 LOD 策略后再进入下一阶段**
8. **崩溃测试套件建立（十四轮终裁，B9 显式验收项）**：退化/边界输入全集（fuzz 种子 + 十三轮退化输入 + 畸形 JSON/未知武器/超界字段）断言不 panic/不段错误/不 OOM，入 CI 一票否决（见 5.2）——Phase 0 建套件、Phase 1 起每轮回归都跑

### Phase 2 — 核心算法（分层）

- **粗层**：FMM 代价场传播（地形+雷达+禁飞区融合，确定性，O(NlogN)），输出全可达域+可行走廊
- **细层**：走廊内运动基元搜索（运动学约束前置）；固定翼 2D Dubins 基元、旋翼机陡爬升基元，高度剖面独立插值满足爬升角
- **回退层**：宏观拓扑路由（FMM 数值不稳/强不连续时启用，接口预留）
- **地形遮蔽约束**（地形进代价函数 + 线段-地形射线求交合法性校验）
- 杜绝无约束搜索回退（走廊细分/重路由/明确报错）
- TargetZone.radius 提前终止
- 走廊内 100 组随机起止回归：量化拟合成功率与单段耗时，对照 3s 预算

### Phase 3 — 输出美化

- Theta\* 去锯齿（细层搜索后处理，消除折线锯齿）
- 样条平滑（Catmull-Rom/Chaikin）
- Dubins 平滑评估：引 `dubins_path(s)` 2D 原型验证 → 通过则接入，不通过则自研 2D Dubins + 高程剖面独立处理
- 贪心双指针抽稀（沿用）
- 平滑器策略链 trait 化
- **链序修正与优先级（九轮共识 + 十轮终端 pose）**：抽稀与平滑的先后须保证最终输出"既平滑又稀疏"——**默认链序**：Theta* 去锯齿 → Dubins/样条拟合 → 贪心抽稀 → **弦高复验**（每段弦高 ≤ 容差，Phase 0 定值；超限回退上一策略环节）；**优先级显式化**：安全（不撞山/不越禁飞限飞） > 运动学约束（机动可飞） > 美化（平滑/抽稀）——美化任一环节与硬约束冲突时以安全/运动学为准并回退；**终端 pose 下放（十轮共识）**：Dubins/样条拟合以终端 pose（航向/高度/速度）为边界条件——发射包线约束在平滑级就满足，而非只在判定级校验（否则合法走廊因终端姿态不满足在判定级反复回退，撞 3s 预算）
- **美化不得改约束（九轮共识 + 十一轮回退语义显式化）**：平滑/抽稀后的航迹仍须满足全部硬约束——下条"后处理二次碰撞校验"为强制复验门，任一违规则回退上一策略环节；**复验失败回退语义（十一轮共识）**：回退链末端（Dubins 失败→样条→原始折线→局部绕行→重路由，见下条）任一版本若仍不过复验——**回退到美化前原始折线路径并显式告警**（`status` 附 `warning: smoothing_failed` + 降级精度度量）：**软美化（平滑/抽稀）不得破坏硬约束**——"美化失败"的正确出口是交付未美化的合法原始路径（宁丑勿违），而非硬返回美化后违规路径或静默丢路径；原始折线本身违规（说明求解层已违约）则直接走修复闭环（局部绕行/重路由），不得以美化级掩盖
- **后处理二次碰撞校验（硬性步骤，全链复验，十轮清单显式化）**：平滑/拟合/抽稀链结束后，对最终航迹强制重跑 地形射线求交 + **禁飞/限飞区包含（A4/A5 硬阈值）** + 雷达代价 + **全路径逐段转角/曲率/爬升角（A3 机动约束）** 校验——**复验清单（十轮共识 + 十二轮 A6）= `{弦高（几何）} ∪ {转弯半径/转弯角/航向连续性（运动学，抽稀删点后相邻段重新检查）} ∪ {终端包线（若终端 pose 下放平滑级）} ∪ {地形净空} ∪ {穿越段累计探测概率（若含穿越雷达探测区）} ∪ {A6 速度-转弯半径自洽（r_min ≥ v²/(g·tan φ_max)）}`**；**复验覆盖抽稀后全路径而非仅末段**（抽稀去点后相邻航段机动约束可能重新超限）；任一违规则回退上一策略环节（Dubins 失败回退样条、样条失败回退原始折线）或明确报错；**修复闭环迭代上界（四轮共识）**：局部绕行 ≤N 次（默认 3）→ 重路由 ≤1 次 → 超限走出口⑤（最优可达点+原因，见 4.2.1），杜绝"校验失败→重路由→再失败"死循环击穿 3s；**局部绕行段自身同样须过机动复验**；预算余量见 5.1

### Phase 4 — 需求补全

## 七、风险与预案

| 风险 | 预案 |
|------|------|
| 3D Dubins 自研风险高 | 降级为 2D Dubins（引 crate 或自研）+ 高程剖面独立插值；3D 联合优化留远期，架构上先接受降级 |
| 地形求交成为性能瓶颈 | 地形 LOD（多分辨率高度图）、降采样、射线步长自适应；Phase 0 先行验证 |
| GeoTIFF 运行时读取慢（瓦片解压开销） | 两级策略：小范围全量加载为内存网格 / 大范围瓦片 LRU 缓存 + Overview；Phase 0 补 GeoTIFF 基准；不达标则运行时预转换内置格式 |
| `dted2` 维护停滞（2024-08 后未更新） | 1.0 稳定版 + 锁版本 + 单测兜底；API 极简（read/get_elevation），必要时可 fork 或自研（DTED 解析约几百行，比 GeoTIFF 简单） |
| 走廊内无解 → 旧式超时复发 | 禁止无约束回退；**无解出口按序：放宽威胁约束 → 放宽目标范围 → 走廊细分/重路由 → 明确报错**（见 4.2.1）；Phase 2 用 100km+3 雷达场景回归验证 |
| 高程基准混用（EGM96 vs 几何/气压高） | 解析层统一归一为 MSL 几何高度（见 4.2.2）；Phase 0 数据契约固定换算参数 + 已知坐标单测样例 |
| 平滑/拟合把合法路径改入山体 | 后处理链末尾强制二次碰撞校验（见 Phase 3 步骤）；违规回退上一策略环节；**仍失败走局部绕行/走廊内重路由，杜绝只判不修**（见 4.5 传导矩阵失败动作列） |
| 内置地形数据与真实地形不一致 | **安全裕度条款**：基于内置地形数据的 FMM 通道在真实地形上校验留裕度（Phase 0 量化差异）；校验失败按 4.5 回退/局部绕行/明确报错；**裕度参数化（四轮共识）**：遮蔽场景（利用地形通道/贴山低飞，A7 硬约束优先）裕度=0，非遮蔽场景保留裕度——裕度 vs 贴山的冲突以 A7 优先、参数可配置，裁决规则文档化 |
| 输入坐标系混用（WGS84/CGCS2000 混标） | `crs.datum` 显式声明 + 默认 WGS 84；混标时以声明为准、不猜测；Phase 0 数据契约单测覆盖 |
| WKT2 参数手抄/核对错误 | 开发期 WKT2 核对 + 已知坐标回代单测（北京/上海经纬度→UTM/GK 对照）CI 断言 |
| SRTM 数据空洞 | SRTM v3+ 已做空洞插值；自研读取时对无效值（-32768）做邻近插值兜底 |
| 经纬度→格网索引映射错误 | coord.rs 单独单测覆盖边界（跨 UTM 带、0°经线、±90°纬度） |
| 走廊内曲线拟合失败率高 | 细层用运动基元搜索替代纯曲线连接；Phase 0 用 100 组随机起止量化成功率，不达标则调整走廊宽度/基元库 |
| 强非平滑代价场退化（增量算法诱惑） | D\* Lite 类增量算法已排除（见 4.4）：静态场景零收益 + 硬边界/雷达尖峰下增量退化为近全量重搜；未来动态威胁走「代价场更新」抽象（FMM 整跑/局部重算） |
| 依赖失控 | 核心依赖锁定 8 个；新增依赖需 benchmark 或需求驱动，写入评审 |
| 纯 Rust 依赖被 C 依赖污染（误开特性） | 静态编译红线写入 3.2.1；CI 用 `cargo tree -e normal` 断言零 C 依赖 + musl target 构建一票否决 |
