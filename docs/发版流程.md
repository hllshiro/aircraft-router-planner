# 发版流程

本文档定义项目的标准发版流程。版本号唯一事实来源为 `Cargo.toml` 的 `[workspace.package] version`。

## 前置条件

- 所有待发布变更已合并到 master 分支
- CHANGELOG.md 的 `[Unreleased]` 部分已填写完整
- 工作区干净（无未提交的修改）

## 发版步骤

### 1. 分析变更内容

读取 `CHANGELOG.md` 的 `[Unreleased]` 部分，判断发版类型：

| 类型 | 版本号变更 | 适用场景 |
|------|-----------|---------|
| MAJOR | X.0.0 | 存在 BREAKING CHANGE 或重大功能变更 |
| MINOR | 0.X.0 | 新增功能、较大优化 |
| PATCH | 0.0.X | 仅 Bug 修复、小幅优化 |

如果 `[Unreleased]` 为空或仅有微小改动，不建议发版。

### 2. 更新版本号

手动编辑 `Cargo.toml`，更新 `[workspace.package] version` 字段：

```toml
[workspace.package]
version = "新版本号"
```

### 3. 整理 CHANGELOG.md

将 `[Unreleased]` 内容移到新版本标题下，添加版本号和发布日期：

```markdown
## [Unreleased]

## [新版本号] - YYYY-MM-DD

### Changed
- 变更内容...

### Fixed
- 修复内容...
```

### 4. 提交变更

```bash
git add CHANGELOG.md Cargo.toml
git commit -m "chore(release): v新版本号"
```

### 5. 创建 Git Tag

```bash
git tag v新版本号
```

### 6. 推送到远程

```bash
git push
git push --tags
```

## 自动化流程

推送 `v*` tag 后，GitHub Actions 会自动触发 `.github/workflows/release.yml`：

1. 校验 tag 与 `Cargo.toml` version 一致
2. 交叉编译四个平台产物：
   - `windows-amd64`
   - `windows-arm64`
   - `linux-amd64`
   - `linux-arm64`
3. 创建 GitHub Release，附带 SHA256SUMS

## 注意事项

- 发布前务必确认 `[Unreleased]` 内容完整，避免遗漏变更
- 版本号遵循 [SemVer](https://semver.org/lang/zh-CN/) 规范
- tag 格式必须为 `v<version>`（如 `v0.7.0`）
- 如果 CI 报错 "tag 与 Cargo.toml version 不一致"，检查版本号是否正确更新
