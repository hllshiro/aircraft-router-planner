# 发版流程

本文档定义项目的标准发版流程。版本号唯一事实来源为 `Cargo.toml` 的 `[workspace.package] version`。

## 前置条件

- 所有待发布变更已合并到 main 分支
- CHANGELOG.md 的 `[Unreleased]` 部分已填写完整

## 发版步骤

### 1. 分析变更内容

读取 `CHANGELOG.md` 的 `[Unreleased]` 部分，判断发版类型：

| 类型 | 版本号变更 | 适用场景 |
|------|-----------|---------|
| MAJOR | X.0.0 | 存在 BREAKING CHANGE 或重大功能变更 |
| MINOR | 0.X.0 | 新增功能、较大优化 |
| PATCH | 0.0.X | 仅 Bug 修复、小幅优化 |

如果 `[Unreleased]` 为空，不建议发版。

### 2. 触发发版 Workflow

在 GitHub 仓库页面 → **Actions** → **release-prepare** → **Run workflow**：

- 输入版本号（如 `0.8.3`，不含 `v` 前缀）
- 点击 **Run workflow**

Workflow 自动完成：
1. 校验版本号格式、tag 不重复、`[Unreleased]` 非空
2. 更新 `Cargo.toml` 版本号
3. 整理 `CHANGELOG.md`（`[Unreleased]` 内容移入新版本标题下）
4. 提交变更 + 创建 tag
5. 推送 commit 和 tag 到 main（使用 `RELEASE_TOKEN` 绕过分支保护）

### 3. 自动发布

tag `v*` 推送后，`.github/workflows/release.yml` 自动触发：

1. 校验 tag 与 `Cargo.toml` version 一致
2. 交叉编译四个平台产物：
   - `windows-amd64`
   - `windows-arm64`
   - `linux-amd64`
   - `linux-arm64`
3. 创建 GitHub Release，附带 SHA256SUMS

## 注意事项

- 发布前务必确认 `[Unreleased]` 内容完整，避免遗漏变更
- 版本号遵循 [SemVer](https://semver.org/lang/zh-CN/) 规范
- tag 格式必须为 `v<version>`（如 `v0.7.0`）
- 如果 CI 报错 "tag 与 Cargo.toml version 不一致"，检查版本号是否正确更新
