## 2. TerrainSource trait（mod.rs）

```rust
pub trait TerrainSource: Send + Sync {
    /// 源级高度查询（经纬度，度）。返回值 = 椭球高（归一化后）。
    /// 空洞（NaN/NoData）或出界 → None
    fn height_at(&self, lon: f64, lat: f64) -> Option<f64>;

    /// 语义采样（空洞分层入口）。默认实现：无掩膜源按 bounds 区分 OOB 与 NoData
    fn sample_at(&self, lon: f64, lat: f64) -> Sample { ... }

    /// 实际覆盖范围（缺瓦/出界判定用）
    fn bounds(&self) -> Option<GeoBounds>;

    /// 分辨率语义描述（等经纬度弧秒 / 地面等距米）
    fn resolution_desc(&self) -> String;
}
```

### 2.1 语义采样结果（Sample / SurfaceClass）

**空洞分层策略（主管 2026-08-04 拍板）**——WATER/NODATA/OOB 三分类 + 湖泊：

```rust
pub enum Sample {
    Land(f64),      // 陆地，携带高度（米，椭球高）
    Water,          // 海洋，高度 0（海平面）
    Lake(f64),      // 内陆湖，携带湖面高度（米，由 DEM 提供）
    NoData,         // 真缺失（NODATA）
    OutOfBounds,    // 超覆盖范围（OOB）
}
```

关键方法：

| 方法 | 语义 |
|------|------|
| `class()` | → SurfaceClass（Land/Water/Lake/NoData/OutOfBounds） |
| `height()` | Land/Lake → 高度；Water → 0；NoData/OOB → None |
| `is_water()` | Water 或 Lake |
| `base_cost(nodata_mult)` | Land/Water/Lake → 1.0；NoData → nodata_mult（初值 5x）；OOB → f32::INFINITY（禁行墙） |
| `los_unblocked()` | Land/Water/Lake → true；**NoData → true（保守端：不遮挡，威胁高估 → 路径避开）**；OOB → false（禁行） |

> **NoData 的 LOS 语义修正**（Phase 0 教训）：原型把空洞一律视为"不遮挡"，导致威胁低估；正式语义改为 NoData 不遮挡（探测概率高估 → 威胁高估 → 路径避开），与 NODATA 高代价通行方向一致。

### 2.2 LOS 遮挡判定（los_blocked）

```rust
pub fn los_blocked<T: TerrainSource>(src, olon, olat, oz, dlon, dlat, dz, len_deg, n) -> bool
```

- 沿方向等距采样 n 点，任一点：`Land(h)` 且 `z ≤ h` → 遮挡；`OutOfBounds` → 遮挡；Water/Lake/NoData → 不遮挡；
- 与威胁模型 `line_of_sight`（threat.rs 内 8 点采样）不同——本函数是通用语义函数，threat.rs 用的是自己的采样实现。

### 2.3 语义退化统计（semantic_degradation_ratios）

在源覆盖范围内均匀采样 n×n 网格，统计 NoData 与 OutOfBounds 占比，供 `stats.degradations` 使用（最坏降级警告）。bounds 未知 → (NaN, NaN)（调用方跳过）。

## 3. ARPK1 自建紧凑格式（builtin.rs）★ 内置数据主实现

### 3.1 文件布局

```
[0..8)     magic "ARPACK1\0"
[8..288)   定长头（LE）：
           format_version u32（=1） / data_version u32 / rows u32 / cols u32 /
           origin_lon f64 / origin_lat f64 / cell_lon_deg f64 / cell_lat_deg f64 /
           z_resolution_m f64 / vertical_datum u8 / resolution_semantics u8 /
           block_compression u8 / reserved u8 / block_size u32（=256）/
           blocks_x u32 / blocks_y u32 / no_data i16 / source[174B]（UTF-8 截断）
[288..320) sha256（数据部分 = 块索引 + 数据块流）
[320..)    块索引：blocks_x*blocks_y × (offset u64 LE, len u32 LE)
[… )       数据块流：每块 = 行内差分 i16 展平（block_size×block_size）
           raw（block_compression=0）或 zstd（block_compression=1，ruzstd 解码）
```

### 3.2 关键常量

| 常量 | 值 | 说明 |
|------|-----|------|
| MAGIC | "ARPACK1\0" | 8 字节魔数 |
| FORMAT_VERSION | 1 | 格式版本 |
| HEADER_SIZE | 288 | 定长头字节数 |
| BLOCK_SIZE | 256 | 块边长（256×256 ≈ 131KB） |
| CACHE_MAX_BLOCKS | 2048 | 解压块缓存上限（≈256MB），FIFO 淘汰 |
| VDATUM_ELLIPSOID / EGM96 | 0 / 1 | 垂直基准编码 |
| SEMANTICS_EQUIANGULAR | 0 | 等经纬度弧秒语义 |
| COMPRESSION_RAW / ZSTD | 0 / 1 | 块压缩方式 |

### 3.3 打开与 fail-fast 校验（open / parse）

**`open(path)`（按需读取，2026-08-07 主管拍板）**：只读头部 + 块索引做结构校验
（O(1)，不读数据块），数据区 mmap 虚拟映射（`memmap2`，pure Rust 零 C 依赖；
物理页按访问加载），块数据按需从映射读取。校验序：

1. 文件长度 ≥ HEADER_SIZE + 32；
2. magic 匹配；
3. format_version == 1；
4. block_size == 256；
5. 头参数非退化（rows/cols/blocks/cell 正）；
6. 块索引完整（offset+len ≤ 文件长）。

**`parse(bytes)`（内存路径，测试/转换校验用）**：结构校验同 1–6，另做
**7. SHA-256 全量校验**：`sha256(块索引 + 数据块流) == bytes[288..320]`。

**`verify_sha()`（可选全量校验）**：开发期/导入后用；发布默认 open 仅结构校验
（O(1)）。数据损坏 → `AppError::Data`（硬故障，禁止静默降级）。

### 3.4 按需解压 + 有界缓存（cell / load_block）

- `open` 数据源为 `Store` enum（Mem / Mmap），`load_block` 按**文件绝对偏移**切片；
- `cell(r, c)`：跨块自动定位 → 缓存命中（锁内查表）→ 未命中锁外解压（多线程不互相阻塞）→ 双检锁插入；
- 块加载：raw 直接 `chunks_exact(2)` 转 i16；zstd 用 `ruzstd::StreamingDecoder` 解压；
- **行内差分还原**：`v[0]` 原样，`v[i] = v[i-1] + v[i]`（wrapping_add）；
- 缓存 FIFO 淘汰：2048 块 ≈ 256MB 上限，防 GMTED2010 全球 17.8 万块随机采样时缓存全部（实测曾 13GB+）；
- `lock_cache` 防 poison panic（崩溃套件要求）。

### 3.5 采样（双线性插值）

```rust
fn sample(&self, lon, lat) -> Option<f64>
```

- 计算网格坐标 (fc, fr) → 四邻格 `cell()` → 双线性插值；
- 越界（c0<0 等）→ None；任一角 NoData → None（**不做空洞插值**——依赖数据源已填洞，见方案 4.2.5）。

### 3.6 Writer（开发期工具）

`write_pack_raw`：生成 raw 块 ARPK1 字节（测试/工具用）；zstd 压缩块由
`phase0/scripts/convert_to_arpk1.py` 产出（GDAL/JP2 解码 + 并行 zstd，开发期流程，
不入运行时）。**产品化转换用 CLI `convert` 子命令（见 3.8）**。

### 3.8 转换命令（CLI `convert`，M2，2026-08-07 主管拍板）

```
aircraft-router-planner-cli convert <in> <out.arpack>
```

- 输入按扩展名自动识别：`.tif/.tiff`、`.dt0/.dt1/.dt2`、`.hgt`（SRTM）→ ARPK1；
- 块级流式转换（内存 O(块) 256²），raw 块（行内差分）+ 完整 SHA
  （索引区 + 数据流，与 `parse` 校验同序）；SRTM 北→南行翻转、DTED 直接网格、
  GeoTIFF cell 读取；
- 转换后自校验：mmap 打开（结构）+ `verify_sha()`（全量）+ 统计输出
  （grid/origin/cell/blocks/体积/耗时）；
- 实测：真实 DTED 3601² → 29.5MB ARPK1 ≈ 0.4s；
- 用户任意大型外部地形 → `convert` → ARPK1 → solver 加载（solver 只吃 ARPK1，
  外部格式按需读取为库层能力 + 转换入参）。

### 3.7 实测数据（docs/phase0_baseline.md 记录）

- parse 1024² ≈ 8.89ms；1000 次采样 ≈ 171.75µs；
- China_Dem_L12：8194×22429 → 76MB（压缩后）；GMTED2010：7200×172800 → 2.311GB；
- **mmap 按需打开（M1）**：真实 gmted2010 2.31GB `open`+采样 ≈ **85ms**（原全量
  读+SHA 5–10s）；采样/端到端规划与全量 parse 逐位一致；
- demo-server 打开 China 76MB ≈ 1s（mmap 后 <100ms 级），全球 2.3GB ≈ 13s → 85ms。

## 4. GSHHG 海陆掩膜（mask.rs）

### 4.1 格式（phase0/scripts/gshhg_mask.py 产出，V2 3 态）

```
[0..16)   magic "ARPACK_MASK_V2__"
[16..64)  header：version u32 BE（=2）/ arcsec u32 BE / rows u32 BE / cols u32 BE /
          lon0 f64 BE / lat0 f64 BE / res_deg f64 BE
[64..)    行索引表：(rows+1) × offset u64 BE（段区绝对偏移，单调不减）
[… )      行段区：每行 [nseg u32 BE, (class u8, start u32 BE, end u32 BE)×nseg]
```

### 4.2 类别语义（主管拍板）

| 类别 | 编码 | 语义 |
|------|------|------|
| Sea | 0 | 海洋（隐式，段不存；海平面高程 0） |
| Land | 1 | 陆地（含南极内陆补全：-85.15°S 以南 + 东南极 -75..-85.15°S 0..160°E） |
| Lake | 2 | 内陆湖（湖面高程由 DEM 提供） |

### 4.3 查询与包装

- `class_at(lon, lat)`：行 RLE 段查找；防御：非有限/越界 → Sea（掩膜外视为海洋，不 panic）；
- `land_lake_ratio()`：陆/湖占比统计；
- **`MaskedSource<T>`**：包装任意 TerrainSource，按掩膜分类映射 `sample_at`：Sea → Water、Lake → Lake(DEM)、Land → 原样（高度由 DEM 提供）。

## 5. SRTM/HGT（srtm.rs）

- `SrtmSource::open(path)`：读取 `.hgt` 裸 16-bit 大端网格（SRTMGL1/3）；
- 文件名解析 `parse_hgt_filename`：`N39E116.hgt` 格式 → (lat, lon)；
- `height_at`：格网映射 + 双线性插值；无效值（-32768）→ None；
- 单文件覆盖 1°×1°（1201×1201 / 3601×3601）。

### 5.1 目录形态（M5：片级 LRU）

- `srtm::open_dir(dir)`：扫描 `.hgt` 片，文件名 + 文件尺寸（1201²/3601²）
  O(1) 建片索引；片全量解码 + LRU（8 片 ≈ 208MB，`tiledir` 框架）；
- 跨片边界采样：双线性 4 角各自 floor 键定位相邻片取原值；
- 单文件 `.hgt` 保持现状（小文件全量）；无效文件（坏名/坏尺寸）跳过。

## 6. GeoTIFF（geotiff.rs）

- `GeoTiffSource::open`：`tiff` crate（image-rs，pure Rust）读取；
- **两级策略（M3，2026-08-07）**：chunk（tile/strip）数 ≤ 64 → open 全量内存网格；
  超过 → chunk 按需解压 + LRU（512 chunk ≈ 128MB，打开 O(IFD) 只读 tag）；
- 地理参考自解析：ModelTiepoint + ModelPixelScale（无旋转；row/col 翻转）；
- GDAL_NODATA 空洞标记 + F32/F64 NaN → 空洞（NoData 语义）；无地理参考拒绝；
- 采样语义与旧 `geotiff` crate 一致（双线性、NaN → None）；
- 实测：tifffile 生成 4096×4096 tiled（256 chunks）→ LRU 按需采样正确；
- 依赖全纯 Rust（tiff ^0.9 等，proj 仅 dev）。

## 7. DTED/DTED2（dted.rs）

- `DtedSource::open`：`dted2` crate 的 `DTEDData::read()`；
- `get_elevation(lat, lon)` 直接匹配 `TerrainSource` 接口；
- 无压缩裸格式，读取性能接近 SRTM（内存常驻/顺序读），Level 0/1/2 支持（DTED2 = 30m）。

### 7.1 目录形态（M4：片级 LRU）

- `dted::open_dir(dir)`：扫描 `.dt0/.dt1/.dt2` 片，**O(1) 只读 UHL（64B）**
  建片索引——布局与 dted2-1.0.0 `parsers::dted_uhl_parser` 一致（实测
  test_data.dt2 验证）：`UHL<level>` + lon(3+2+2+符号) + lat(3+2+2+符号) +
  lon_interval×4 + lat_interval×4 + accuracy×4 + 跳过15 + lon_count×4 +
  lat_count×4 + 跳过25；interval 单位 0.1 弧秒 → `/36000` 转度；
- 采样按经纬度 floor 键定位片 → dted2 全量读片 + LRU（8 片 ≈ 208MB）；
- 跨片边界采样：双线性 4 角各自定位相邻片取原值；
- 单文件 `.dt*` 保持现状（dted2 全量）；无效文件（UHL 不可解析）跳过。

## 8. 片级目录源框架（tiledir.rs，M4/M5 共用）

- `TileDirSource`：片索引（TileMeta：path/origin/cell）+ `(floor(lon), floor(lat))`
  1°×1° 查找表（O(1) 定位）+ 片级 LRU（`Arc<dyn TerrainSource>` 缓存，8 片上限）；
- `TileOpener`：DTED/SRTM 各自的片打开工厂；`tile(idx)` 缓存命中 clone Arc，
  未命中锁外 open + 双检插入；
- `sample` 双线性 4 角跨片定位（边界格点由 floor 键自然落相邻片）；
- `open_source` 目录分发（mod.rs）：按格式优先级 **GeoTIFF > DTED > SRTM**
  （主管 2026-08-07 拍板）；GeoTIFF 目录暂不支持——目录含 `.tif` 时明确报错
  指引传单文件（单文件 GeoTIFF 已按需），避免静默降级到低优先级格式。
