## 三、覆盖范围总结

### 3.1 已覆盖的核心功能域

1. **输入解析与校验**（config.rs + crash_suite.rs）：JSON 解析、schema 兼容（旧版拒）、坐标合法性、zone 语义（NoFly/Restricted/Obstacle）、武器、多机、必经点——覆盖充分。

2. **FMM 代价场传播**（costfield.rs + field_build_compare.rs）：常量场/退化网格/空网格/越界、backtrack 路径重建、serial vs parallel vs local bit-exact 对比——覆盖充分。

3. **地形系统**（terrain/*.rs + crash_suite.rs）：SRTM/DTED/GeoTIFF/Builtin 四种源的打开、采样、跨片、缓存、行向判定、overview、掩膜（Land/Water/Lake/NoData/OOB/Forbidden）、LOS 遮挡——覆盖充分。

4. **路径平滑链**（smooth.rs + crash_suite.rs）：Theta* 去锯齿（共线压缩/入航向约束/圆弧过渡）、Chaikin/Catmull-Rom/Dubins/GreedySimplify、策略链回退语义、复验器（地形净空/禁飞/转角/半径/弦高/爬升角/雷达）、旋翼机分支——覆盖充分。

5. **绕障 Patch 系统**（patch.rs）：凸包/膨胀/可见图/Dijkstra、圆障碍切点绕行、多障碍/多簇串接、雷达边权、地形边权、restricted 弦判据——覆盖充分。

6. **Solver 集成**（solver.rs + regress_phase0.rs）：端到端平原/禁飞绕行/restricted 剖面/雷达绕行/必经点/多机/时间预算/垂直剖面/push_out_of_walls/LOS mask/走廊细分——覆盖充分。

7. **确定性门禁**（determinism.rs）：同输入双跑逐字节一致——覆盖充分。

8. **崩溃防御**（crash_suite.rs + phase0 crash_suite.rs）：空/NaN/Inf/极端坐标/退化网格/旧 schema/截断数据——覆盖充分。

### 3.2 覆盖相对薄弱的区域

1. **多机交叉检测（P6-C）**：仅有 4 个单元测试（交叉/远离/高度分离/单机），缺少多机（3+）交叉、平行编队、时序交叉等边界场景。

2. **武器系统**：config.rs 中仅验证解析和默认射程，缺少武器包络（heading/alt/speed 范围）对路径规划影响的集成测试。

3. **DegradedTimeout 超时**：仅 1 个测试（1ms 预算），缺少渐进超时（部分完成）场景。

4. **ARPK1 mmap 大文件**：仅用合成小数据验证 mmap 与 parse 一致性，缺少真实大文件（>1GB）的压力测试。

5. **旋翼机端到端**：solver.rs 中旋翼机仅出现在多机场景的第二架，缺少旋翼机单独的端到端规划测试（绕障/平滑/verify 全链）。
