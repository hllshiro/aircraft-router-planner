> 本文件为阶段 1 完成后的交付物，**暂不实现**）
> 依据：2026-08-11 两轮圆桌讨论（6 轮×3 人）收敛共识；方案 v0.20 约束

## 1. 背景与动机

阶段 1 完成了增量止血，但存在结构性残余问题：

| 问题 | 表现 | 阶段 1 的缓解 | 残留 |
|------|------|--------------|------|
| 粗网格混叠 | FMM 1024² 网格 + 7.5as 地形采样下，窄走廊/尖角/短障碍的几何信息失真（zz29 相位差、zz30 长段漏峰同源） | A 统一采样口径 + verify 无上限全采样 | 粗层走廊本身仍是 1024² 网格上的路径，局部几何不精确 |
| C 类未区分 | "几何无解"与"算法缺陷"都表现为 smoothing_failed / no_solution | C 输出失败 JSON（**能看见**失败，仍**不能分类**） | 无法回答"这条路到底存不存在" |
| 双口径系统性对齐 | check（Theta\* 贪心跳点）与 verify（全链复验）测量口径 | A 抽原语（terrain_sample_count / terrain_point_clearance）消除漂移 | 两套代码仍各跑各的，无架构级保证 |

阶段 2 的目标：**在保持确定性、复用阶段 1 底座的前提下，把"粗层走廊 + 局部精确裁决"结构化**，使 C 类问题获得确定性答案（合法路径 or 明确 no_solution），不再依赖"回退运气"。

## 2. 架构总览

**两级分辨率 + 裁决器**，叠加在阶段 1 之上（不替代任何阶段 1 机制）：

```
粗层（现有）                         细层（新增）
───────────────────────              ───────────────────────────
FMM 场（1024²，7.5as）     ──走廊──▶  patch 定位器（失败点/必经点触发）
Theta*/Dubins/抽稀/复验                patch 内约束可见图搜索（精确）
（阶段 1 语义全部保留）                  patch 路径 + 走廊骨架拼接
                                          └─▶ C 类裁决器（几何无解 vs 缺陷）
                                                  │
                                          verify（复用阶段 1 原语）→ 交付 / no_solution + 分类诊断
```

关键思路：**粗层只管"方向性走廊"（全局拓扑），细层只管"局部精确性"（patch 内几何）**。
细层不用更细的地形格（数据契约不允许），而用**可见图（visibility graph）+ 精确几何检查**——
可见图不做网格离散化，从根上消除混叠。

## 3. 组件设计

### 3.1 粗层走廊（复用现有）

- **复用**：现有 FMM 代价场（含 restricted 墙/雷达软罚/地形）与平滑链输出路径，作为走廊骨架。
- **走廊定义**：骨架路径 ± 走廊半径 `CORRIDOR_R = 20km`（按车辆 turn_radius 缩放，
  `max(20km, 4×turn_radius)`）。走廊仅用于**限制细层搜索范围**，不参与细层路径判定。
- **不新增**：粗层不做任何分辨率提升（保持阶段 1 行为，回归风险为零）。

### 3.2 patch 定位器（新增）

- **触发源**：
  1. 最终 verify 的**硬闸失败点**（地形净空 / 禁飞/受限区净距 issue 的坐标）——聚类成触发区；
  2. **必经点**（mid_waypoint）自身——必经点约束在粗层可能被混叠吞掉（zz33 掉头教训）；
  3. 段级 smoothing_failed 阶段（阶段 1-C 诊断 JSON 里的失败阶段）的路径局部。
- **patch 形状**：以触发点为中心的矩形/走廊段，尺寸 `PATCH_R = 30km`（约 4×7.5as 格 × 16，
  覆盖一个窄走廊的完整绕行机动空间）；多个触发点距离 < PATCH_R 时合并为一个 patch。
- **输出**：`(patch 矩形, 走廊骨架切片, 边界锚点)`——边界锚点 = 骨架与 patch 边界的交点，
  作为细层路径的固定起终点。

### 3.3 patch 内约束可见搜索（新增）

- **障碍建模**：patch 内禁飞/受限区多边形（取粗层走廊内的部分）→ **凸化**（分治凸分解，
  凹多边形拆凸，控制顶点规模）；地形净空不作为障碍，而是作为**边合法性检查**（见下）。
- **可见图**：顶点 = 障碍多边形凸顶点 + patch 边界锚点 + 必经点；边 = 顶点两两连线
  **通过合法性检查**（复用阶段 1-A 原语）：
  - 地形净空：`terrain_point_clearance`（Land/Water 净空、NoData/OOB 不阻断）沿边采样
    （`terrain_sample_count`，无上限——patch 内边长 ≤ 60km，采样量可控）；
  - 禁飞/受限区：边不与任何障碍多边形相交（解析求交，复用现有 zone_segment 判定）；
  - 转角/半径：与骨架邻接段组成的转角、三点外接圆半径，用阶段 1-B 容忍带判定
    （容忍带内 warn 不阻断）。
- **搜索**：Dijkstra（可见图顶点数百级，O(V²) 边判定一次性构建后走最短路）。
  边权重 = 几何长度 × (1 + 软罚)（雷达软罚复用现有模型）。**确定性**（无随机）。
- **与粗层的关系**：patch 内路径独立于粗网格；粗层路径只提供边界锚点（方向性）。

### 3.4 C 类裁决器（新增）

patch 搜索 + Dubins 精确裁决（复用现有 dubins.rs + arc_transition）：

```
可见图最短路 P
   ├─ P 不存在（无边连通起点→终点）
   │    └─ 判定：几何无解（C 类真无解）→ no_solution + 分类 JSON（"geometrically_impossible"）
   ├─ P 存在 → Dubins/样条拟合（复用平滑链）→ verify（复用阶段 1 原语）
   │    ├─ verify ok → 交付（patch 路径并入走廊骨架）
   │    ├─ verify 硬闸失败 → 判定：几何无解（障碍不可规避）→ no_solution + 分类 JSON
   │    └─ verify 仅软项超带 → 判定：算法缺陷（路径存在但拟合不足）→
   │         记录缺陷类别（转角/半径/弦高/爬升），尝试 patch 内重跑（改 Dubins 参数/换锚点）；
   │         仍失败 → no_solution + 缺陷分类 JSON（供后续迭代，而非静默回退）
   └─（回归护栏）任何路径 → 阶段 1-D 硬闸复验，raw 回退不交付（语义不变）
```

**裁决器的价值**：把"失败"从一坨 JSON 变成**分类结论**——
`geometrically_impossible`（无解，接受）vs `fitting_defect:turn/radius/chord/climb`（缺陷，可迭代）。
这正是阶段 1 评估中"C 类真无解 vs 算法缺陷未区分"的架构级答案。

### 3.5 拼接与接缝

- patch 路径与走廊骨架在边界锚点处拼接；接缝 ±10km 重跑平滑链（复用阶段 1 全链）保证
  接缝处运动学合法（转角/半径连续）。
- 拼接后全路径过最终 verify（阶段 1 原语）——任何拼接引入的违规都被兜住。

## 4. 复用 vs 新增清单

| 复用（零改动） | 新增 |
|---------------|------|
| FMM 代价场（粗层走廊） | patch 定位器（失败点聚类/必经点触发） |
| 平滑链全部阶段（Theta\*/Catmull/Dubins/抽稀） | 可见图构建器（障碍凸化 + 边合法性） |
| 阶段 1-A 原语（terrain_sample_count / terrain_point_clearance） | patch 内 Dijkstra 搜索 |
| 阶段 1-B 容忍带 / 阶段 1-C JSON 诊断 / 阶段 1-D 硬闸 | patch 路径拼接器 + 接缝重跑 |
| zone_segment 解析求交 / radar 软罚模型 | C 类裁决器（分类 JSON） |

**新增代码规模估算**：~800–1200 行（可见图 ~300、patch 定位/拼接 ~300、裁决器 ~200、
凸化 ~200），集中在 solver.rs 或新模块 `patch.rs`。

## 5. 与阶段 1 的关系

- **叠加**：阶段 2 只在"粗层全链失败 / 硬闸失败"时触发 patch 流程；成功路径完全走阶段 1
  语义（零行为变化，回归护栏 = 现有 168+ 测试）。
- **底座**：阶段 1-A 原语是细层边合法性检查与最终 verify 的**同一套测量**——没有阶段 1-A，
  细层与验收又会漂移成第三条口径。
- **顺序**：阶段 2 的工作量依赖阶段 1 稳定（失败分类输入来自阶段 1-C JSON）。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 可见图顶点爆炸（patch 内多边形多） | V² 边构建超时 | 障碍凸化 + patch 尺寸上限（30km）+ 顶点数上限（≥64 顶点拆 patch） |
| patch 接缝违规 | 拼接路径 verify 失败 | 接缝 ±10km 重跑平滑链；失败则扩张 patch 重试一次 |
| 边界锚点选择不当（起终点被障碍困住） | patch 内无解误判"几何无解" | 锚点取走廊骨架最近可见点（骨架与 patch 边界的首个可通交点） |
| 粗层走廊本身错（FMM 无解） | patch 无法触发 | 不触发 patch（粗层 no_solution 语义不变）；patch 只处理"粗层有解但平滑失败" |
| 确定性回归 | 新组件引入非确定行为 | 可见图 + Dijkstra 全确定；CI 全量测试 + 逐位一致构建（v0.20 红线） |

## 8. 原型验证计划

- **P1（定位器 + 可见图最小原型）**：单 patch、单凸障碍、无地形——验证可见图最短路径
  与 C 类裁决（几何无解 vs 缺陷）的分类正确性。
- **P2（拼接 + 接缝）**：两段走廊骨架 + 一个 patch——验证边界锚点与接缝重跑。
- **P3（历史案例端到端）**：在 zz29 / zz32 / zz33（C 类代表）上对比：
  - 旧行为：回退/锯齿/no_solution 无分类；
  - 新行为：`geometrically_impossible` 或 `fitting_defect` 分类 + 合法路径或明确 no_solution。
- **验收标准**：
  1. C 类案例 100% 获得分类结论（不再"一坨 JSON"）；
  2. 能解出的 C 类案例路径通过阶段 1-B/C/D 全闸；
  3. 全量测试（lib 168+ + crash 33 + regress + compare）无回归；
  4. release 逐位一致构建通过。

## 9. 明确排除项（圆桌共识，不做）

- **全局 Hybrid A\*/Eikonal 曲率**：粗网格混叠会把曲率信息打没（高维状态在 1024² 网格上
  不可分辨），收益不成比例。
- **RRT\*/概率采样**：违反确定性构建红线（v0.20），直接排除。
- **clothoid 回旋线**：边际收益低（现有 Dubins 圆角已覆盖常见工况），新增复杂度不划算。

## 10. 结论

两级分辨率架构是阶段 1 止血后的**结构性收敛**：粗层走廊复用零改动，细层可见图
在确定性红线内提供局部精确裁决，C 类裁决器把"无解"与"缺陷"分开。工作量 11–17 人日，
主要风险（顶点爆炸、接缝）有明确缓解。**建议在阶段 1 稳定运行 + 3–5 个 C 类案例
积累后启动 P1 原型**；是否实施由主管拍板。
