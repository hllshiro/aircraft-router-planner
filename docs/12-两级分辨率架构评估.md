## 1. 背景与动机

阶段 1 完成了增量止血，但存在结构性残余问题：

| 问题 | 表现 | 阶段 1 的缓解 | 残留 |
|------|------|--------------|------|
| 粗网格混叠 | FMM 1024² 网格 + 7.5as 地形采样下，窄走廊/尖角/短障碍的几何信息失真（zz29 相位差、zz30 长段漏峰同源） | A 统一采样口径 + verify 无上限全采样 | 粗层走廊本身仍是 1024² 网格上的路径，局部几何不精确 |
| C 类未区分 | "几何无解"与"算法缺陷"都表现为 smoothing_failed / no_solution | C 输出失败 JSON（**能看见**失败，仍**不能分类**） | 无法回答"这条路到底存不存在" |
| 双口径系统性对齐 | check（Theta\* 贪心跳点）与 verify（全链复验）测量口径 | A 抽原语（terrain_sample_count / terrain_point_clearance）消除漂移 | 两套代码仍各跑各的，无架构级保证 |

阶段 2 的目标：**在保持确定性、复用阶段 1 底座的前提下，把"粗层走廊 + 局部精确裁决"结构化**，使 C 类问题获得确定性答案（合法路径 or 明确 no_solution），不再依赖"回退运气"。

## 2. 架构总览

**两级分辨率 + 裁决器**，叠加在阶段 1 之上（不替代任何阶段 1 机制）：

```
粗层（现有）                         细层（新增）
───────────────────────              ───────────────────────────
FMM 场（1024²，7.5as）     ──走廊──▶  patch 定位器（失败点/必经点触发）
Theta*/Dubins/抽稀/复验                patch 内约束可见图搜索（精确）
（阶段 1 语义全部保留）                  patch 路径 + 走廊骨架拼接
                                          └─▶ C 类裁决器（几何无解 vs 缺陷）
                                                  │
                                          verify（复用阶段 1 原语）→ 交付 / no_solution + 分类诊断
```

关键思路：**粗层只管"方向性走廊"（全局拓扑），细层只管"局部精确性"（patch 内几何）**。
细层不用更细的地形格（数据契约不允许），而用**可见图（visibility graph）+ 精确几何检查**——
可见图不做网格离散化，从根上消除混叠。

## 3. 组件设计

### 3.1 粗层走廊（复用现有）

- **复用**：现有 FMM 代价场（含 restricted 墙/雷达软罚/地形）与平滑链输出路径，作为走廊骨架。
- **走廊定义**：骨架路径 ± 走廊半径 `CORRIDOR_R = 20km`（按车辆 turn_radius 缩放，
  `max(20km, 4×turn_radius)`）。走廊仅用于**限制细层搜索范围**，不参与细层路径判定。
- **不新增**：粗层不做任何分辨率提升（保持阶段 1 行为，回归风险为零）。

### 3.2 patch 定位器（新增）

- **触发源**：
  1. 最终 verify 的**硬闸失败点**（地形净空 / 禁飞/受限区净距 issue 的坐标）——聚类成触发区；
  2. **必经点**（mid_waypoint）自身——必经点约束在粗层可能被混叠吞掉（zz33 掉头教训）；
  3. 段级 smoothing_failed 阶段（阶段 1-C 诊断 JSON 里的失败阶段）的路径局部。
- **patch 形状**：以触发点为中心的矩形/走廊段，尺寸 `PATCH_R = 30km`（约 4×7.5as 格 × 16，
  覆盖一个窄走廊的完整绕行机动空间）；多个触发点距离 < PATCH_R 时合并为一个 patch。
- **确定性要求（2026-08-12 圆桌）**：patch 合并顺序、边界锚点「最近」选取（含平局）
  必须显式 tie-break——按**顶点整数索引 / 坐标字典序**（勿用浮点 `==` 判等，浮点比较
  不可靠）；内部集合用 BTreeMap/固定序，禁止依赖 HashMap 迭代序（Rust HashMap 迭代
  序随机，会破坏契约 2 的逐位一致构建）。
- **输出**：`(patch 矩形, 走廊骨架切片, 边界锚点)`——边界锚点 = 骨架与 patch 边界的交点，
  作为细层路径的固定起终点。

### 3.3 patch 内约束可见搜索（新增）

- **障碍建模 —— 只凸化硬墙（2026-08-12 圆桌修订）**：
  - **禁飞区 / 障碍物（硬墙）**：取粗层走廊内的部分 → **凸化**（分治凸分解，凹多边形
    拆凸，控制顶点规模）。凸化必须基于**已膨胀几何**（膨胀 = `max(0.5×转弯半径)` clamp
    [2km, 10km]，满足契约 9「绕行留出机动空间不得贴边」）。
  - **限飞区（restricted）不凸化、不进入可见图**：契约 7（高度层语义区分）+ 契约 8
    （受限区穿行判据 = 直线穿行带（弦）非整圆面、底部穿行恒优于顶部绕飞）要求限飞区
    保留 3D 高度语义——2D 凸化会把"可底部穿行"误判为"必须绕行"。patch 内限飞区
    处理沿用粗层原判据（直线弦带 + 高度判定 + 15° 爬升 + 升限），作为**段合法性检查**
    而非障碍；**P1 直接排除限飞区触发 patch 的场景**（P2 再评估与弦判据的集成）。
- **可见图**：顶点 = **硬墙**障碍多边形凸顶点 + patch 边界锚点 + 必经点；边 = 顶点两两连线
  **通过合法性检查**（复用阶段 1-A 原语）：
  - 地形净空：`terrain_point_clearance`（Land/Water 净空、NoData/OOB 不阻断）沿边采样
    （`terrain_sample_count`，无上限——patch 内边长 ≤ 60km，采样量可控）；
  - 硬墙（禁飞/障碍）：边不与任何凸化后障碍多边形相交（解析求交，复用现有
    zone_segment 判定）；
  - 限飞区：边按**原弦判据 + 高度判定**（剖面/穿行语义同粗层），与硬墙判定分开实现；
  - 转角/半径：与骨架邻接段组成的转角、三点外接圆半径，用阶段 1-B 容忍带判定
    （容忍带内 warn 不阻断）。
- **搜索**：Dijkstra（可见图顶点数百级，O(V²) 边判定一次性构建后走最短路）。平局
  显式 tie-break（顶点索引序）。**确定性**（无随机）。
- **边权重与成本口径（2026-08-12 圆桌收敛）**：
  - **P1（无地形单凸障碍）**：几何长度 × (1 + 软罚)——但**明示雷达/空洞（NODATA/OOB）
    语义在 patch 内降级**，任何因降级导致的差异进 `stats.degradations`（契约 5：空洞
    "任意形态给可用结果，最坏降级警告"）；
  - **P2（地形/雷达进 patch）**：边权重并入**FMM 同源代价**（雷达软约束 ×(1+200×(p+geom))、
    NODATA/OOB 5x 通行），避免「可见图最短」与「verify 全链复验」两套口径在接缝处冲突。
- **与粗层的关系**：patch 内路径独立于粗网格；粗层路径只提供边界锚点（方向性）。

### 3.4 C 类裁决器（新增）

patch 搜索 + Dubins 精确裁决（复用现有 dubins.rs + arc_transition）：

```
可见图最短路 P
   ├─ P 不存在（无边连通起点→终点）
   │    └─ 判定：几何无解（C 类真无解）→ no_solution + 分类 JSON（"geometrically_impossible"）
   │       ※ 适用范围不含限飞区触发的 patch（限飞区不进入可见图，见 §3.3）
   ├─ 搜索被截断（顶点数/尺寸上限命中，§7 风险缓解）
   │    └─ 判定：search_truncated（工具限制，非几何结论）→ no_solution + 分类 JSON +
   │        stats.degradations 警告（2026-08-12 圆桌新增：被上限截断 ≠ 几何无解，
   │        必须与 geometrically_impossible 区分，否则污染 no_solution 确定性语义；
   │        判定优先级高于 geometrically_impossible，避免污染历史案例归因）
   ├─ P 存在 → Dubins/样条拟合（复用平滑链）→ verify（复用阶段 1 原语）
   │    ├─ verify ok → 交付（patch 路径并入走廊骨架）
   │    ├─ verify 硬闸失败 → 判定：几何无解（障碍不可规避）→ no_solution + 分类 JSON
   │    └─ verify 仅软项超带 → 判定：算法缺陷（路径存在但拟合不足）→
   │         记录缺陷类别（转角/半径/弦高/爬升），尝试 patch 内重跑（改 Dubins 参数/换锚点）；
   │         仍失败 → no_solution + 缺陷分类 JSON（供后续迭代，而非静默回退）
   └─（回归护栏）任何路径 → 阶段 1-D 硬闸复验，raw 回退不交付（语义不变）
```

**裁决器的价值**：把"失败"从一坨 JSON 变成**分类结论**——
`geometrically_impossible`（无解，接受）/ `search_truncated`（工具限制，非结论）/
`fitting_defect:turn/radius/chord/climb`（缺陷，可迭代）。
这正是阶段 1 评估中"C 类真无解 vs 算法缺陷未区分"的架构级答案。

**分类结论出口（2026-08-12 圆桌修订，实施前由主管拍板）**：
阶段 1-C 诊断 JSON（`smooth_chain_failed` / `fmm_attempts_exhausted`）走 **stderr**
（`eprintln!`），stdout 仍是 status 四态 + vehicles[].status，schema 0.20 的
`deny_unknown_fields` 不校验 stderr。因此分类结论有两个候选出口：
1. **stderr 诊断 JSON（零 schema 负担）**：沿用阶段 1-C 通道，但验收标准 1「分类结论
   100% 可获」要求**下游消费方（CLI 用户/demo）同步读 stderr**——stderr 需作为契约面
   约定格式（event 名 + 结构）；
2. **stdout 结构扩展**：需版本表升级（schema 0.21）或挂既有 `stats.degradations` /
   warnings 字段（零版本升级，但表达力有限）。
**推荐**：分类 JSON 走 stderr（与阶段 1-C 一致），另在 stdout `stats.degradations`
挂一条汇总（"classified: geometrically_impossible/search_truncated/..."），
兼顾可获性与零 schema 负担。

### 3.5 拼接与接缝

- patch 路径与走廊骨架在边界锚点处拼接；接缝 ±10km 重跑平滑链（复用阶段 1 全链）保证
  接缝处运动学合法（转角/半径连续）。
- 拼接后全路径过最终 verify（阶段 1 原语）——任何拼接引入的违规都被兜住。

## 4. 复用 vs 新增清单

| 复用（零改动 / 仅接线） | 新增 |
|---------------|------|
| FMM 代价场（粗层走廊） | patch 定位器（失败点聚类/必经点触发，含显式 tie-break） |
| 平滑链全部阶段（Theta\*/Catmull/Dubins/抽稀） | 可见图构建器（**硬墙**凸化 + 边合法性，限飞区不凸化） |
| 阶段 1-A 原语（terrain_sample_count / terrain_point_clearance） | patch 内 Dijkstra 搜索（BTreeMap/固定序） |
| 阶段 1-B 容忍带 / 阶段 1-C JSON 诊断 / 阶段 1-D 硬闸 | patch 路径拼接器 + 接缝重跑（扩张重试设硬上限+固定步长） |
| zone_segment 解析求交 / radar 软罚模型 / 限飞区弦判据+高度判定（复用粗层判据） | C 类裁决器（分类 JSON：geometrically_impossible / search_truncated / fitting_defect） |
| B9 崩溃套件（扩展：零障碍 patch / <3 顶点凸化 / 锚点重合 / tie-break / search_truncated） | CI 确定性门禁（同输入双跑逐字节比对） |

**新增代码规模估算**：~800–1200 行（可见图 ~300、patch 定位/拼接 ~300、裁决器 ~200、
凸化 ~200），集中在 solver.rs 或新模块 `patch.rs`。

## 5. 与阶段 1 的关系

- **叠加**：阶段 2 只在"粗层全链失败 / 硬闸失败"时触发 patch 流程；成功路径完全走阶段 1
  语义（零行为变化，回归护栏 = 现有 168+ 测试）。
- **底座**：阶段 1-A 原语是细层边合法性检查与最终 verify 的**同一套测量**——没有阶段 1-A，
  细层与验收又会漂移成第三条口径。
- **顺序**：阶段 2 的工作量依赖阶段 1 稳定（失败分类输入来自阶段 1-C JSON）。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 可见图顶点爆炸（patch 内多边形多） | V² 边构建超时 | 硬墙凸化 + patch 尺寸上限（30km）+ 顶点数上限（≥64 顶点拆 patch） |
| 搜索被上限截断误判"几何无解" | 污染 no_solution 确定性语义 | **search_truncated 第三态**（§3.4），优先级高于 geometrically_impossible（2026-08-12 圆桌新增） |
| 限飞区 2D 凸化抹平高度层 | 误杀可底部穿行解，违反契约 7/8 | 限飞区**不凸化**，沿用弦判据+高度判定；P1 排除限飞区触发 patch（2026-08-12 圆桌新增） |
| patch 接缝违规 | 拼接路径 verify 失败 | 接缝 ±10km 重跑平滑链；失败则扩张 patch 重试一次——**重试设硬上限 + 固定步长**，保终止性与确定性（契约 2） |
| 边界锚点选择不当（起终点被障碍困住） | patch 内无解误判"几何无解" | 锚点取走廊骨架最近可见点（骨架与 patch 边界的首个可通交点），平局按索引/字典序 |
| 可见图成本口径与 verify 不一致 | 接缝处 verify 翻车 | P1 明示雷达/空洞语义降级进 stats.degradations；P2 边权并入 FMM 同源代价（2026-08-12 圆桌收敛） |
| 粗层走廊本身错（FMM 无解） | patch 无法触发 | 不触发 patch（粗层 no_solution 语义不变）；patch 只处理"粗层有解但平滑失败"；region 截断类已修（§11.1） |
| 确定性回归 | 新组件引入非确定行为 | 可见图 + Dijkstra 全确定；显式 tie-break（patch 合并/锚点/平局）；BTreeMap/固定序禁 HashMap 迭代序；CI 双跑逐字节比对门禁（2026-08-12 圆桌新增） |

## 8. 原型验证计划

- **P1（定位器 + 可见图最小原型）**：单 patch、单凸障碍、无地形、**无限飞区**——
  验证可见图最短路径与 C 类裁决（几何无解 / search_truncated / 缺陷）的分类正确性。
  **范围收窄（2026-08-12 圆桌）**：排除限飞区触发 patch（§3.3）、排除 100km+ 贴墙
  走廊多 patch 串接（§11.2）——P1 只验证单 patch 单障碍分类链路。
- **P2（拼接 + 接缝）**：两段走廊骨架 + 一个 patch——验证边界锚点（tie-break）与
  接缝重跑（扩张重试硬上限）；限飞区弦判据接线。
- **P3（历史案例端到端）**：在 zz29 / zz32 / zz33（C 类代表）上对比：
  - 旧行为：回退/锯齿/no_solution 无分类；
  - 新行为：`geometrically_impossible` / `search_truncated` / `fitting_defect`
    分类 + 合法路径或明确 no_solution。
- **验收标准**：
  1. C 类案例 100% 获得分类结论（stderr 诊断 JSON + stats.degradations 汇总，出口
     按 §3.4 拍板结果执行）；
  2. 能解出的 C 类案例路径通过阶段 1-B/C/D 全闸；
  3. 全量测试（lib 170 + crash 33 + regress + compare）无回归；
  4. release 逐位一致构建通过；CI 双跑逐字节比对门禁通过。

## 9. 明确排除项（圆桌共识，不做）

- **全局 Hybrid A\*/Eikonal 曲率**：粗网格混叠会把曲率信息打没（高维状态在 1024² 网格上
  不可分辨），收益不成比例。
- **RRT\*/概率采样**：违反确定性构建红线（v0.20），直接排除。
- **clothoid 回旋线**：边际收益低（现有 Dubins 圆角已覆盖常见工况），新增复杂度不划算。

## 10. 结论

两级分辨率架构是阶段 1 止血后的**结构性收敛**：粗层走廊复用零改动，细层可见图
在确定性红线内提供局部精确裁决，C 类裁决器把"无解"与"缺陷"分开。工作量 11–17 人日，
主要风险（顶点爆炸、接缝）有明确缓解。**建议在阶段 1 稳定运行 + 3–5 个 C 类案例
积累后启动 P1 原型**；是否实施由主管拍板。

## 11. 已知边界与后续发现（2026-08-11）

> 本节记录两级方案落地前主管指定的两项边界：**问题 2 已修复**（粗层 region 截断
> 误报 no_solution）与**问题 1 担忧**（patch 不兜底粗层无解的完整边界）。实施两级
> 方案时应在此节基础上更新风险表。

### 11.1 问题 2：粗层 region 截断误报 no_solution —— 已修复（阶段 1 收尾）

- **现象**：任务 bbox 近正方形 + 硬墙（NoFly/Obstacle）占满 region 一个方向时，
  绕行路径被迫超出 region（region 外无代价场）→ coarse FMM no path → 误报
  `no_solution`。实测绕出 region 仅 0.05°（5.5km）即通（zz_region_block2）。
- **修复**：`region_of` 后叠加 `expand_region_for_walls`——硬墙 bbox 超出任务区域时
  并入 region（多边形墙余量 0.15°、圆墙 0.03°；Restricted 不画墙不纳入）；grid 按
  外扩后 span 等比上调（保持 cell ≈ 原值，5c2 软罚带物理宽度不变，避免 real_bad
  教训 / 锯齿）。回归测试 zigzag36；全量 170+33+2+1 过。
- **圆墙余量 0.03° 的教训（zz19）**：圆墙 bbox 大（半径数十 km），若按多边形同样
  加 0.15° 余量，本已贴近任务边界的圆会被撑出 region（外扩 0.05°）→ 代价场格点
  微移 → terrain 高度墙格点翻转 → masked 场 FMM 无解 → probe unmasked → 丢
  restricted 剖面语义。**粗层 terrain 墙对 region/grid 微变敏感**是已知现象——
  两级方案的细层边合法性检查（`terrain_point_clearance` 无上限采样）从根上消除
  这类敏感性（不依赖网格格点巧合）。

### 11.2 问题 1 担忧：patch 不兜底粗层 FMM 无解 —— 记录为架构边界

风险表第 4 行（"粗层走廊本身错（FMM 无解）→ patch 无法触发"）的完整边界如下：

1. **patch 只处理"粗层有解但平滑失败"**：两级方案触发条件是"粗层全链失败 / 硬闸
   失败"（3.2 patch 定位器）。**coarse FMM no path 不触发 patch**——粗层无解时
   直接走既有 `no_solution` 语义（warning "coarse FMM no path"），两级方案不改变
   该输出。
2. **region 截断类粗层无解已在阶段 1 修复（11.1）**——实施两级方案后该根因的
   "粗层无解"场景减少；但**其余粗层无解根因仍不兜底**：
   - 真无通道（障碍/地形/OOB 围死起点或目标格点）；
   - OOB/NODATA 墙 + 硬墙组合截断走廊；
   - restricted 墙组合导致 masked 场无解（probe unmasked 保底，但语义降级）。
   这些场景两级方案保持"粗层 no_solution"输出，**不会**因细层可见图而"救活"——
   若后续需要覆盖，应作为**粗层正确性修复**（如 11.1），而非 patch 机制。
3. **贴墙走廊长（100km+）时工作量高于乐观估计**：verify 硬闸失败点沿全程分布时，
   patch 定位器会把走廊切成多个 patch（合并距离 PATCH_R=30km 上限），拼接与接缝
   重跑（3.5）次数随之增加——patch 定位器 + 拼接的工作量（§6 中 1–2 + 3–4 人日）
   取下限时不成立。实施时建议按"多 patch 串接"为默认工作模式做原型（P2 扩展）。
