# 06 — 输入输出契约与数据校验

> 设计依据：技术方案 4.2.1（默认参数表/无解出口/status 契约）

## 1. 总览

CLI 采用 **文件 I/O** 形态：`arpcli plan --file <file> --out <path>`。所有字段 `deny_unknown_fields`。

```
main.rs 流程：
  read_input → Input::from_json_str（畸形 → input_invalid: malformed_json）
  → config::validate（InputValidator：退化输入 → input_invalid + 原因码）
  → solver::solve（成功 → Output::success）
```

**status 四态契约**：

| status | 含义 | 触发 |
|--------|------|------|
| `success` | 规划成功 | 正常完成 |
| `degraded_timeout` | 超时返回可用结果 | 预算耗尽 |
| `no_solution` | 确定性无解 | 全出口链耗尽 |
| `input_invalid` | 非法/退化输入 | 解析/校验层拦截 |

> `no_solution` 不是失败，是确定性结论；非零退出只留给硬故障。

## 2. 输入契约（Input）

顶层结构（v0.21 契约拍平）：

```rust

    pub aircraft: Vec<AircraftInput>,      // 飞行器数组（必填非空）
```

### 2.5 Weapon（武器）

```rust
pub struct Weapon {
    pub weapon_type: WeaponType,         // aam / agm / bomb
```

**默认射程**：aam [5,40] / agm [3,120] / bomb [1,15] km

### 2.6 ParamsOverride

| 字段 | 默认值 |
|------|--------|

## 4. 错误体与错误码

```rust
pub enum AppError {
    Io(std::io::Error),               // → internal_error
    Json(serde_json::Error),          // → input_invalid: malformed_json
    InputInvalid(InputInvalidReason), // → input_invalid + 原因码
    NoSolution(String),               // → no_solution
    DegradedTimeout(String),          // → degraded_timeout
    Data(String),                     // → data_error
    Internal(String),                 // → internal_error
}
```

**InputInvalidReason**：malformed_json / illegal_coordinate / out_of_bounds / degenerate_start_equals_target / target_in_no_fly / mid_waypoint_in_no_fly / radar_overlap_no_fly / missing_aircraft / vehicle_params_inconsistent

## 5. InputValidator

入口防线：畸形/退化输入在进入算法前拦截。

校验顺序：
1. aircraft 空数组 → `missing_aircraft`
2. 逐机校验：重复 id、profile 域校验、start/target 坐标、间距 < 100m → 拒绝、禁飞区检查
3. 雷达 ∩ 禁飞区
4. 限飞区高度区间
5. 参数覆盖数值域（回落默认）

## 6. 默认参数表

编译期常量，输入未提供时使用。`detection_curve`/`base_p` 已于 2026-08-13 标定。
