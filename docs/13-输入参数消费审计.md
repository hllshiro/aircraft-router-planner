## 0. 结论速览

输入 JSON 里存在四类「解析但未消费」的问题，集中在：

1. **整个 CRS 坐标系声明是死的**：`crs`（datum / vertical / input_projection）与 `output_crs`（projection）被解析、有 `to_datum()`/`to_geo()` 方法，但**这些方法从未被调用**——解算器始终按 WGS84 经纬度工作。
2. **`parameters`（ParamsOverride）13 字段中 7 个是死的**：`main_budget_ms`、`degrade_budget_ms`、`z_resolution_m`、`fine_success_threshold`、`coarse_cell_m`、`default_weapon_radius_km`、`weapon_map` 被 `merge()` 拷进 `DefaultParams`，但 solver 从不读它们。
3. **「保留/占位」字段**：`red_forces.sams`（整个 SAM 类型）、`radar.radar_type`、`profile.detection_probability`、`start_pose.heading_deg`、`zone.height_semantics`、`terrain.resolution_m`/`vertical_datum`、`weapon.fuze_type`/`target_ref`。
4. **两处 stale 注释**：`VehicleInput.mid_waypoints`（高度实际已消费）与 `WeaponEntry.envelope`（实际已消费）的「仅解析」注释与代码不符。

## 12. 与 CLI options 的关系

CLI `plan` 现有 options：`--input`、`--output`、`--terrain`、`--mask`、`--grid`。

| CLI option | 对应 JSON 字段 | 关系 |
|---|---|---|
| `--input` / `--output` | 无 | 纯 I/O 路径 |
| `--terrain` | `terrain.path` | **覆盖**（`--terrain` 优先，`solver.rs:148-151`；2026-08-20 起无默认探测，缺省 = 无地形 + 警告降级） |
| `--mask` | `terrain.mask_path` | **覆盖**（`--mask` 优先，`solver.rs:189-192`；2026-08-20 起不再自动探测默认掩膜，仅显式指定时启用） |
| `--grid` | `parameters.coarse_cell_m`（死字段） | 无实际重复（`coarse_cell_m` 本身是死字段） |

> 语义冲突提示：`--grid` 与 `parameters.coarse_cell_m` 都在表达「网格分辨率」，但实际只有 `--grid` 生效（`coarse_cell_m` 是死字段），二者职责需要二选一定案。

## 13. 清理建议清单（决策见 14）

### A. 可直接删（纯死字段，无消费，删后需评估 schema 0.20 兼容）

- `terrain.resolution_m` / `terrain.vertical_datum`
- `zone.height_semantics`
- `weapon.fuze_type` / `weapon.target_ref`
- `parameters` 中 7 个死字段：`main_budget_ms`、`degrade_budget_ms`、`z_resolution_m`、`fine_success_threshold`、`coarse_cell_m`、`default_weapon_radius_km`、`weapon_map`

### B. 需先接线（字段有语义，但未实现消费）

- `profile.detection_probability` → 接进威胁代价（隐蔽突防折算）
- `zone.height_semantics`（AGL 语义）→ 实现 AGL→MSL 换算（若决定保留该字段）

### C. 需修正注释（代码已消费，但 doc 注释称「仅解析」）

- `VehicleInput.mid_waypoints`（高度实际已消费）
- `WeaponEntry.envelope`（实际已消费）

### D. 语义冲突待定

- `--grid`（CLI）vs `parameters.coarse_cell_m`（JSON 死字段）——二选一定案

## 14. 最终决策与实施记录（v0.21，2026-08-19）

主管拍板并已实施于 v0.21（对应技术方案 v0.21 修订记录与 CHANGELOG [0.2.1]）：

| 事项 | 决策 |
|------|------|
| A 类纯死字段 | **硬删除**（连同 `CrsConfig`/`OutputCrsConfig` 类型与未用的 `to_datum()`），契约定为 v0.21（破坏性变更）；携带旧字段输入被拒（`input_invalid: malformed_json`） |
| B 类有语义未消费字段（`start_pose.heading_deg` / `profile.detection_probability` / `zone.height_semantics`） | **移出契约，保留设计线索**（后续另行立项：Dubins 初始朝向 / 隐蔽突防折算 / AGL 换算），见技术方案 v0.21 修订记录第 2 条 |
| `DefaultParams` 同名死字段 | 与契约字段**一并删除**；另修正事实：`default_weapon_map()` 为**零调用点**（原 D 节清单未列出），随 `weapon_map` 一并删除 |
| D 类语义冲突（`--grid` vs `coarse_cell_m`） | **二选一消解**：网格分辨率仅由 CLI `--grid` 表达，`parameters.coarse_cell_m` 删除 |
| `schema_version` | **输入输出全删**（六轮共识 C11 修订）：版本号不再作为输入输出的重要参数，契约版本追溯改由 CHANGELOG/技术方案版本承担 |
| crate 版本 | `0.2.1`（`scripts/bump_version.sh`，2026-08-19） |
| demo 同步 | `demo-server`/`demo/web` 输入构建同步移除全部已删字段（计划 Task 7 另行执行，见 plans/2026-08-19-输入契约精简.md） |

| `mission` 包裹层 | **删除**，字段拍平至顶层（`aircraft`/`red_forces`/`no_fly_zones`/`restricted_zones`/`obstacles`/`terrain`/`parameters`） | 无（§2 原 mission 内字段消费点不变，仅路径层级变化） |
| 顶层 `start`/`target` | **删除**，起终点逐机显式（`aircraft[].start/target` 必填） | 无（`resolve_target_ref` 缺省回退逻辑随之删除，目标直接消费） |
| `start_pose` / `VehiclePose` | **删除**（与 `Waypoint` 重复类型），统一为 `aircraft[].start` | 无（原 `start_pose.lon/lat/alt_m` 消费点改读 `start`） |
| `target_ref` | **删除**魔法字符串（缺省 / `"mission.target"` / `"lon,lat[,alt]"`），目标结构化 `aircraft[].target` | 无（每机目标直接显式） |
| 顶层 `weapons` 数组 + `weapon_id` | **删除**，武器移入 `aircraft[].weapon`（`weapon_type` 必填、`range_km?`、`envelope?`，出现即启用） | 无（`effective_range_km`/环带目标集消费不变，关联逻辑简化） |
| `zone_type` 键 | **删除**，三数组为唯一类型标记（解析层按数组注入内部字段；旧键 → `malformed_json`） | 无（`Zone::is_wall()` 内部字段读取不变） |
| `vehicle`/`VehicleInput` 等术语 | **全量改名** vehicle（车辆）→ aircraft（飞行器），契约面 + 内部 + 文档 | 无（纯改名；`vehicle_params_inconsistent` 原因码名保留） |
