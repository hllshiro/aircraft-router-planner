> 状态：**讨论稿**（待主管拍板清理方向，尚未改动任何代码）
> 目的：逐字段核查 `Input` 契约中每个参数的「是否被解算器实际消费」，并核对与 CLI options 的关系，为后续字段清理/接线提供依据。
> 覆盖范围：`cli/src/config.rs`（输入契约定义）↔ `cli/src/solver.rs` / `cli/src/threat.rs` / `cli/src/smooth.rs`（消费点）。
> schema_version 基线：`0.20`

## 0. 结论速览

输入 JSON 里存在四类「解析但未消费」的问题，集中在：

1. **整个 CRS 坐标系声明是死的**：`crs`（datum / vertical / input_projection）与 `output_crs`（projection）被解析、有 `to_datum()`/`to_geo()` 方法，但**这些方法从未被调用**——解算器始终按 WGS84 经纬度工作。
2. **`parameters`（ParamsOverride）13 字段中 7 个是死的**：`main_budget_ms`、`degrade_budget_ms`、`z_resolution_m`、`fine_success_threshold`、`coarse_cell_m`、`default_weapon_radius_km`、`weapon_map` 被 `merge()` 拷进 `DefaultParams`，但 solver 从不读它们。
3. **「保留/占位」字段**：`red_forces.sams`（整个 SAM 类型）、`radar.radar_type`、`profile.detection_probability`、`start_pose.heading_deg`、`zone.height_semantics`、`terrain.resolution_m`/`vertical_datum`、`weapon.fuze_type`/`target_ref`。
4. **两处 stale 注释**：`VehicleInput.mid_waypoints`（高度实际已消费）与 `WeaponEntry.envelope`（实际已消费）的「仅解析」注释与代码不符。

## 12. 与 CLI options 的关系

CLI `plan` 现有 options：`--input`、`--output`、`--terrain`、`--mask`、`--grid`。

| CLI option | 对应 JSON 字段 | 关系 |
|---|---|---|
| `--input` / `--output` | 无 | 纯 I/O 路径 |
| `--terrain` | `mission.terrain.path` | **覆盖**（`--terrain` 优先，`solver.rs:147-150`） |
| `--mask` | `mission.terrain.mask_path` | **覆盖**（`--mask` 优先，`solver.rs:196-199`） |
| `--grid` | `parameters.coarse_cell_m`（死字段） | 无实际重复（`coarse_cell_m` 本身是死字段） |

> 语义冲突提示：`--grid` 与 `parameters.coarse_cell_m` 都在表达「网格分辨率」，但实际只有 `--grid` 生效（`coarse_cell_m` 是死字段），二者职责需要二选一定案。
