# 01 — 项目概览与系统架构

> 系列文档第 1 篇。面向技术人员：先看本篇建立全局认知，再按需深入各模块文档。
> 配套设计文档：`docs/技术方案.md`（v0.20，终审定稿，含全部共识/裁决记录）。本文是"设计蓝图 × 实现现状"的映射。

## 1. 项目是什么

**AircraftRouterPlanner** 是一个**确定性 3D 航路规划 CLI 引擎**（Rust 实现，2024 edition）：输入蓝方兵力/武器、红方雷达/地空导弹部署、禁飞/限飞区、地形数据与飞行器性能参数，输出每架飞机的航路点集（经纬度 + MSL 高度）。

核心定位一句话：

> 在保证自身安全（不撞山、不越禁飞/限飞区、满足机动约束）的前提下，规划进入**武器发射阵位**（而非贴目标点）的航路，并规避红方雷达探测。

### 1.1 关键特性速览

| 特性 | 说明 |
|------|------|
| 分层解耦 | 粗层 FMM 代价场（定走廊）→ 细层运动基元/平滑（保可行）→ 全链复验 |
| 确定性 | 固定种子逐位可复现（跨平台），构建期禁 FMA + 固定 target-cpu |
| 性能硬指标 | 每百公里 ≤ 3s（端到端，典型值），绝对不能崩溃（B9） |
| 多机支持 | `vehicles` 数组，一次代价场共享、每机独立 FMM 回溯 |
| 多源地形 | SRTM/HGT、GeoTIFF、DTED/DTED2、自建 ARPK1 紧凑格式（Zstd） |
| 威胁建模 | 球形雷达 + 探测概率衰减 + LOS 地形遮蔽 + 压制修正 + 多雷达概率并集 |
| 输出契约 | `status` 四态（success / degraded_timeout / no_solution / input_invalid）+ `schema_version` |
| 交付形态 | 单二进制（stdin/stdout JSON 管道）+ 内置地形文件；Demo 为开发期工具不随发布版分发 |

### 1.2 历史背景（重构动机）

项目前身 `simple-router-planner`（CLI 二进制 `rplan-cli`，v0.4.0）为纯 Rust 的确定性 3D 航路规划引擎，采用"宏观拓扑路由 → 安全飞行走廊 → 加权 A\*"三层架构。实测存在硬伤：

| 类别 | 问题 | 后果 |
|------|------|------|
| 性能 | 100km+ 多雷达场景超时 | 宏路由中间点导致某段走廊内无解 → 回退**无约束搜索**（O(N³) 灾难） |
| 物理正确性 | 路径钻入地下（-4500m） | 无地形/地面约束，A\* 把"从雷达球体下方穿过"视为合法 |
| 功能缺口 | 限飞区无法表达、固定翼/旋翼不区分、输出不平滑、无地形输入、蓝方武器未实现 | 多项原始需求未覆盖 |

结论：问题出在算法与实现，不在语言。基于原始功能需求重构，命名 **AircraftRouterPlanner**。

## 2. 目标与硬指标

| 指标 | 定义 | 出处 |
|------|------|------|
| 性能 B8 | 每百公里 ≤ 3s（端到端 wall-clock：进程启动 → stdout 输出可用结果集）；航程按比例线性外推（300km ≤9s、1000km ≤30s），无隐藏封顶 | 方案 5.1 |
| 崩溃 B9 | 绝对不能崩溃；崩溃 = panic/段错误/OOM；合法处置 = 合法错误码 + JSON 输出 | 方案 5.2 |
| 确定性 | 相同种子输出逐位一致（跨平台）；构建期 IEEE754 严格语义 + `-C target-feature=-fma` + 固定 target-cpu | 方案 5.2 |
| 交付 | 单二进制（Linux musl / Windows MSVC 静态）+ 内置地形数据文件；纯 Rust 零 C 依赖 | 方案 1.3 / 3.2.1 |

**验收口径**：`每百公里 ≤ 3s` 为典型值。双基准验收——① 法定基准：真实 SRTM + 多雷达负载；② 交付基准：主管提供的内置地形数据包（全球 152.87m 或中国 76.44m，二选一）。验收只看端到端，不做每过程精细子预算（环节占比仅为初始分配参考）。

## 3. 技术选型

### 3.1 语言：Rust（2024 edition）

Rust 满足三条硬性需求：性能（无 GC、零成本抽象）、确定性（无未定义行为）、交付（cargo 交叉编译生态）。2024 edition 由主管拍板（2026-08-04）：
- `unsafe_op_in_unsafe_fn` 默认 deny，契合 B9"绝对不能崩溃"；
- 不触及浮点语义，跨平台逐位一致仍由 `-fma` 控制；
- 唯一前提：构建工具链 ≥ 1.85（本机 1.95 满足）。

### 3.2 依赖清单（核心 8 + 数据源 3，全部纯 Rust）

| 库 | 用途 | 版本锁定 |
|----|------|---------|
| serde / serde_json | JSON 契约 | ^1 |
| rand | 确定性随机（FNV-1a 噪声场等） | ^0.10（geo 非可选依赖，勿降 0.8） |
| nalgebra | 3D 向量/矩阵基元 | 0.35（默认特性，禁 blas） |
| rstar | R-Tree 空间索引 | ^0.12（geo 锁死，勿升 0.13） |
| geo（含 geo-types） | 测地线距离/方位 | 0.33.1 |
| thiserror | 错误类型 | ^2（dted2 带 ^1，双版本可接受） |
| clap | CLI 参数 | 4.6（derive） |
| geotiff | 运行时 GeoTIFF 读取 | 0.1（锁具体版本） |
| dted2 | 运行时 DTED/DTED2 读取 | 1.0.0 |
| ruzstd | 纯 Rust Zstd 解码（ARPK1 内置格式） | 0.7 |
| sha2 | ARPK1 数据 SHA-256 校验 | 0.10 |

**静态编译红线（3.2.1）**：① nalgebra 仅默认特性禁 blas；② geo 不启用 proj feature（投影自研）；③ flate2 保持 rust_backend；④ ruzstd 纯 Rust（不引 libzstd C）。CI 用 `cargo tree -e normal` 断言零 C 依赖 + musl target 构建一票否决。

**GDAL 定位**：仅开发期离线预处理工具（任意 DEM → 重采样/裁剪/填洞/重投影），不进运行时。

## 5. 分层架构（核心设计）

针对旧项目"A\* 均匀网格 + 运动学事后剪枝"的失败模式，新架构采用**分层解耦**：

```
┌─────────────────────────────────────────────────────────────────┐
│ 粗层：FMM 快速行进法（2D 水平网格 + 50m 固定层高语义）              │
│   代价场 = 地形（硬阈值+软代价）× 禁飞/限飞硬墙 × 雷达代价          │
│   → 输出：全可达域（单次传播）+ 可行走廊（回溯）                    │
│   → 多机共享同一传播场（一次 FMM 多目标回溯）                      │
├─────────────────────────────────────────────────────────────────┤
│ 细层：走廊内运动基元/平滑链（运动学约束前置保证可行）                │
│   Theta* 去锯齿 → Catmull-Rom 样条 → Dubins 拟合 → 贪心抽稀        │
│   受限区剖面（底部穿行 / 顶部绕飞）与绕行弧由 solver 切分           │
├─────────────────────────────────────────────────────────────────┤
│ 后处理：全链复验门（verify_path）                                  │
│   {地形净空} ∪ {禁飞/限飞包含} ∪ {转弯半径/转角/航向连续/爬升角}     │
│   ∪ {弦高} ∪ {A6 物理自洽} ∪ {雷达累计探测概率（软告警）}           │
│   任一失败 → 回退上一策略环节；全链失败 → 交付原始折线 + 显式告警    │
├─────────────────────────────────────────────────────────────────┤
│ 回退层：无解出口链（不回归无约束搜索）                              │
│   ① 压制重算（仅显式声明）→ ② 探测概率穿越评估 → ③ 放宽目标半径     │
│   → ④ 走廊细分/重路由 → ⑤ 明确报错（no_solution + 原因码）          │
└─────────────────────────────────────────────────────────────────┘
```

### 5.1 为什么是 FMM 而不是 A\*

方案 4.4 的澄清：A\* 是图搜索算法，与维度无关；真正不适合的是"均匀网格离散化 + 运动学事后剪枝"。FMM 的优势：

| 维度 | FMM（定案主方案） |
|------|------------------|
| 可达域 | 单次传播给出**全场**可达域，直接命中"到达 B 点一定范围"需求 |
| 多机 | 代价场全场复用（架构级红利），每机只做一次 O(NlogN) 回溯 |
| 确定性 | 无启发式误差、确定性堆实现 |
| 地形 | 天然进代价函数（不撞山 + 软代价） |

**网格维度定稿（十三轮共识）**：2D 水平网格 + 50m 固定层高垂直分层（不自适应，层数 = ceil(任务高度范围/50m) + 安全余量）；粗层水平 1-2km（当前实现 `--grid 256` 自适应任务区域）、细层水平 152.87m（数据分辨率）；`z_resolution_m: 50` 写入数据契约。

### 5.2 关键架构决策（共识速查）

| 决策 | 内容 | 实现状态 |
|------|------|---------|
| 运动学约束前置 | 固定翼/旋翼机各自基元；旋翼机悬停/极小转弯半径 r→0 显式建模为合法机动，禁止除零退化 | ✅ 已实现（smooth_options_for + 复验机型分支） |
| 速度为核心输入 | 速度影响 ρ = v²/(g·tan φ_max)、爬升率、雷达暴露时间、发射包线 | ✅ 已实现（A6 自洽校验） |
| 发射阵位 = 区域 | TargetZone 支持区域对象；到达 = 进入区域 ∧ 落点 ∈ [Rmin,Rmax] ∧ 发射包线 | ⚠️ 部分实现（区域几何 + 半径判定；Rmin–Rmax 环带与发射包线为 Phase 4 后续） |
| 多机契约 | vehicles 数组；一次 FMM 多目标回溯；代价场缓存按源键共享；3s 预算按机线性 | ✅ 已实现（共享 field，每机独立 FMM） |
| 多机交叉检测 | 输出后处理检测空间交叉，检出显式告警 | ❌ 未实现（时间维 out-of-scope，检测项计划中） |
| 无解出口链 | ①压制 → ②穿越评估 → ③放宽半径 → ④细分/重路由 → ⑤报错 | ⚠️ 部分实现（②穿越评估当前为直线直穿替代 + 告警；③④为后续） |
| status 契约 | success / degraded_timeout / no_solution / input_invalid + 原因码 | ✅ 已实现（input_invalid 全量；degraded_timeout/no_solution 机制就绪） |
| 输出坐标口径 | 经纬度（度，WGS84）+ MSL 米（x=经度 y=纬度） | ✅ 已实现 |

## 6. 端到端数据流

```
stdin / --input JSON
   │
   ▼
main.rs: read_input → Input::from_json_str（畸形 JSON → input_invalid: malformed_json）
   │
   ▼
main.rs: config::validate（InputValidator：A=B / B在禁飞区 / 雷达∩禁飞区 / 车辆参数 A6 自洽）
   │  └─ 失败 → input_invalid + 原因码（不进入算法）
   ▼
solver::solve（核心链路）：
   1. TerrainSource 构建（none 平面 / ARPK1 文件）
   2. 车辆规格提取（vehicles 空 → 默认单机 v1）
   3. 任务区域计算（起点+target 包围盒 + 0.15° 缓冲，方形）
   4. Zone 集合合并（no_fly + restricted + obstacles）+ CircleIndex
   5. 语义代价场（Land/Water/Lake=1.0，NoData=5x，OOB=INF；NoFly/Obstacle 硬墙）
   5c. 禁飞墙膨胀（物理转弯半径 0.5×，clamp [2km,10km]）+ 过渡带软罚（BFS 距离变换 2 格）
   5b. 雷达静态代价（膨胀半径内 cost ×(1+200×(并集概率+深穿惩罚))）
   6. 每机：分段 FMM（start → mid_waypoints → target，共享代价场）→ 回溯
      → 受限区剖面切分（底部/顶部决策）→ 平滑链 → 全链复验 → 输出契约
   │
   ▼
stdout / --output JSON（schema_version + status + vehicles[].path + stats）
```
