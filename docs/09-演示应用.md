## 2. 后端（demo/server）

### 2.1 POST /api/plan

- 接收完整 Input JSON（schema 0.20）→ `serde_json::to_string` → 管道写入 CLI 二进制 stdin → 读取 stdout → 透传 Output JSON；
- **转发前把 terrain.path 相对路径解析为绝对路径**（`resolve_terrain_path` 多候选，见 2.4）——开发模式 `data/xxx.arpack` 与独立包形态都能让 CLI 打开；
- CLI 二进制定位（`cli_bin`）：`ARP_CLI` 环境变量优先（存在才用，误设回退候选）→ exe 同目录 / 上级目录（含 `.exe` 后缀，独立包形态：`install/demo/demo-server.exe` → `install/aircraft-router-planner-cli.exe`）→ 常见 workspace 相对路径（`target/release/` 等）；
- CLI 非零退出 / 空输出 → 返回 `input_invalid` + `INTERNAL_SERVER_ERROR` 错误体（不崩溃）。

### 2.2 POST /api/terrain

- 请求：`{ path, bbox: [min_lon, min_lat, max_lon, max_lat], grid: [nx, ny]? }`（grid 默认 [64,64]，上限 128）；
- 通过 `open_source` 打开 ARPK1 文件（**进程内缓存**：OnceLock<Mutex<HashMap<path, Arc<TerrainSource>>>）；
- 响应：`{ nx, ny, bbox, resolution, source_bounds, heights: (number|null)[] }`；
- `height_at` 返回 NaN → null（serde_json 不支持 NaN 序列化）；
- bbox 非法（min ≥ max / 非有限）→ `{ error: "invalid bbox" }`。

### 2.3 服务启动（单进程）

```rust
Router::new()
    .route("/api/plan", post(plan_route))
    .route("/api/terrain", post(terrain_route))
    .fallback_service(ServeDir::new(web_dir).not_found_service(ServeFile::new(index)))
    .layer(tower_http::cors::CorsLayer::permissive());   // 开发期全放开 CORS
// 绑定 0.0.0.0:{DEMO_PORT|3001}
```

- 静态目录：环境变量 `DEMO_WEB_DIR` 覆盖，默认 exe 同目录 `web-dist/`（独立包形态 `install/demo/web-dist/`）；
- 端口：环境变量 `DEMO_PORT`，默认 3001。

### 2.4 可移植地形路径解析（resolve_terrain_path，2026-08-10）

前端默认地形为相对路径 `data/east_asia_7p5as.arpack`（开发模式 cwd=workspace 根命中）；独立包把地形放 `install/` 根（`east_asia_7p5as.arpack`），`demo-server.exe` 位于 `install/demo/`。依次尝试：

1. 绝对路径原样（存在才用）；
2. cwd 原样 / cwd 去首段（`data/x` → `x`）；
3. exe 同目录原样 / exe 上级原样；
4. exe 同目录去首段 / exe 上级去首段（`install/demo` → `install/east_asia_7p5as.arpack`）。

解析失败（用户显式填了不存在的路径）→ 保留原样由 CLI 报错。

## 3. 前端（demo/web）

### 3.1 类型与坐标工具（types.ts）

- **契约类型**：完全对齐 `cli/src/config.rs`（InputConfig / Mission / VehicleInput / VehicleProfile / Radar / Zone / TerrainConfig / ParamsOverride / PlanResult / VehicleOutput / TerrainInfo）；
- **坐标工具**：

```ts
geoToLocal(wp, ref): [x, y, alt]     // 等距近似：x=(lon−refLon)×111320×cos(lat0)，y=(lat−refLat)×110574
localToGeo(v, ref): Waypoint
```

- **默认配置**（北京近郊演示场景）：start (115.9, 39.8) → target (116.8, 40.3)，固定翼 250 m/s / r=442m / 爬升角 15°，地形 `data/east_asia_7p5as.arpack`（537MB，GMTED2010 东亚 7.5as，70–135°E × 15–55°N，2026-08-10 与发布版 install/ 默认地形对齐）；`parseVehicleTargetRef` 解析每机 `target_ref` 自定义坐标（"lon,lat[,alt]"）。

### 3.2 API 层（api.ts）

- `planRoute(config)` → POST /api/plan；
- `fetchTerrain(path, bbox, grid)` → POST /api/terrain（error 字段 → throw）；
- `sceneBounds(config)`：start/target + 各机 `start_pose` + 每机 `target_ref` 包围（点击设置终点在场景外时 bbox 自动扩展），跨度 = max(实际距离 × 1.4, 最小 2.5° 经度 × 2.2° 纬度)（2026-08-06 起替代固定 ±600km；保证地形网格覆盖全场景 + 余量）。

### 3.3 App.tsx（主界面状态）

- 状态：`config` / `result` / `loading` / `clickMode`（'start' | 'target' | 'midpoint' | 'polygon' | null）/ `pickVehicleIdx`（每机拾取目标下标）/ `editingZoneId` / `terrainData` / `terrainError`；
- 地形加载 effect：source=path 且 path 存在时按 sceneBounds 采样 **96×96**（跨度变大后保持地形精细度，server 上限 128；取消机制 + 错误覆盖层）；
- `handlePlan`：调用 planRoute，网络错误 → 本地构造 `input_invalid/NETWORK_ERROR` 结果；
- 交互回调：
  - `handleGroundClick`：地面拾取——start/target → 该机 `start_pose` / `target_ref`（每机独立，2026-08-10）；midpoint → 添加必经点（高度取该机起点高度，保持模式可连续添加）；polygon → 追加多边形顶点；起点/终点选定后自动退出拾取模式；
  - `handleMidpointMove`：拖动必经点 → 更新 `mid_waypoints[index]` 经纬（高度保留）；
  - `handleRadarMove`（拖动雷达）、`handleZoneMove`（拖动区域）。

### 3.4 Scene3D.tsx（3D 场景）

- `@react-three/fiber` Canvas + OrbitControls + Grid；
- 圆形 zone → 24 边局部平面多边形（`circleToLocalPolygon`）；多边形 → 顶点映射；
- `GroundClickPlane`：地面拾取（防抖：同一位置 400ms 内只生效一次；雷达拖动后 400ms 抑制误设）；
- 渲染：StartMarker / TargetZone（全局目标蓝色）+ 每机自定义目标（红色小标记）/ RadarSphere（探测球+地面盘）/ NFZPrism（禁飞区棱柱，高度带）/ PathLine（多车独立颜色）/ TerrainMesh（地形网格高度着色，96×96 采样）/ **MidpointMarker（必经点黄色可拖动小球，Alt+点击新增由地面拾取层处理）**；
- 统一 zScale 缩放（`computeZScale`，0.08 clamp [3,20]，无地形=1）：地形、航路、起终点、必经点、雷达、NFZ、顶点全部同一尺度（2026-08-08 修复航路钻进夸张山体）；`TerrainMesh` 网格可点选（onPick 返回地形表面交点，替代 y=0 平面穿透，点击精度修复）；
- 轨道：起点/终点/雷达/区域/必经点均可拖拽（点击模式联动；必经点拖动期间禁用 OrbitControls + 结束后 400ms 抑制地面拾取）。

### 3.5 ControlPanel.tsx（参数面板）

- **全局起终点输入已删除**（2026-08-10）：mission.start/target 保留在内部状态（默认值）仅作契约兜底；每机区块独立设置：
  - 飞行器列表（多机增删，至少保留 1 架）：机型（固定翼/旋翼机）、速度、转弯半径、爬升角、升限、起点位姿（场景拾取 + 坐标编辑）；
  - **每机独立目标**：`target_ref` 自定义坐标（"lon,lat[,alt]"）编辑 + "恢复全局目标"（清除后跟 mission.target）；每机"设置起点/设置终点"按钮进入场景拾取模式；
  - **必经点序列**（增删 + 坐标编辑 + 🖱 点击场景添加必经点按钮，连续添加；场景黄色小球可直接拖动）；
- 雷达：增删/经纬/半径/类型（early_warning/tracking/fire_control）；
- 禁飞区：圆形（经纬/半径/高度带/类型：no_fly/restricted/obstacle）+ 多边形（顶点表格编辑 + 场景拾取顶点）；
- 地形源：none/builtin/path + 路径输入；
- 探测概率参数（radar_inflation / p_cross / detection_curve / suppression_delta / los_mask_coef）；
- 结果面板：每车路径长度/路点数/复验警告（warnings）、全局降级记录（stats.degradations）、FMM 耗时与 LOS 检查次数。

## 4. 启动方式

### 独立包（install/demo/，推荐给别人/其他机器）

复制整个 `install/`（CLI exe + data/ + demo/），进入 `install/demo/` 双击 `start-demo.bat`（Linux/macOS：`./start-demo.sh`）——启动 demo-server（单进程 :3001 同时提供 API 与前端页面）→ 自动打开浏览器 http://localhost:3001，即开即用（无需 Rust/Node/npm）。

### Windows 开发一键（项目根）

双击项目根 `start_demo.bat`：自动检查/构建 CLI 与 demo-server（`rebuild` 参数强制重建）→ 启动后端 :3001 与前端 :5173 → 自动打开浏览器（双进程：demo-server 提供 API、Vite dev server 提供前端）。

### 手动分步

```bash
cargo build --release -p aircraft-router-planner-cli
cargo build --release -p demo-server
cargo run --release -p demo-server &        # :3001（含静态前端，生产构建后单进程即用）
cd demo/web && npm install && npm run dev   # :5173（开发热更新）
```

Linux/macOS：`bash demo/start.sh`（按 Git Bash/npm 编写）。

## 6. 与发布的边界

- 核心发布物（单二进制 + 默认地形/掩膜）**不含 Demo**（主管裁决）；`install/` 完整安装包（CLI + data/ + demo/）为可选分发形态，Demo 在其中独立可运行、可删；

- Web 只支持圆形禁飞区编辑；多边形在契约中保留，前端仅预览/拾取编辑。
